# 04｜端到端研究流程

> AXIOM v2.2 設計規格｜文件 ID AX-04｜狀態：待實作、待驗收｜2026-10-19

## 研究與任務的分工

Research 是長期容器；ResearchVersion 固定資料、語意、假設、切分、公式集合與 budget。Run 是一次操作，Attempt 是同操作的重試。新資料、修改假設、不同搜尋組態都建立新 ResearchVersion 或新 Run，不改舊證據。僅重試完全相同操作時保留 run_id。

## 研究版本狀態轉移

| 起始 | 操作與前置條件 | 目標 | 拒絕情境 |
|---|---|---|---|
| DRAFT | validate，語意／資料版本完整 | VALIDATING | 缺欄回 422，不啟動搜尋 |
| VALIDATING | 品質檢查完成且無阻擋 | READY | 不通過回 DRAFT，保存報告 |
| READY | 提交 search run，交易預留預算 | QUEUED | 配額不足 429，狀態不變 |
| QUEUED | worker 取得有效租約 | RUNNING | 已取消不得取得新租約 |
| RUNNING | 全部必要子任務終態且產物已提交 | REVIEW | 部分失敗則結果可為證據不足，不假報全成功 |
| REVIEW | 有權審核者核准有效 EvidenceBundle | PUBLISHED | 缺證據、撤銷或自我核准均阻擋 |
| REVIEW | 拒絕，保存 ReviewDecision=REJECTED | REVIEW | 重做另建 DRAFT 版本，舊審核不可覆寫 |
| QUEUED / RUNNING | cancel 接受後停止派送、撤銷租約 | CANCELLED | 完成與取消競態依 AX-38 交易序列裁定 |
| RUNNING | 不可恢復的基礎設施失敗 | FAILED | 合法歧義／無規律不是基礎設施失敗 |

v1 不提供暫停／恢復使用者操作；checkpoint 僅供 crash retry。PAUSED 是後續版本保留值，v1 輸入回 INVALID_TRANSITION。CANCELLED／FAILED 版本可建立新 run 前須另建 READY 的新版本；發布不可被重跑覆蓋。PUBLISHED 可附撤銷記錄及最新證據有效性，不直接刪歷史。

## Run phase 與結果

phase 為 PROFILING／FEASIBILITY／RETRIEVING／PLANNING／SEARCHING／FITTING／VALIDATING／FINALIZING；MVP 未啟用記憶或 AI 時直接略過，保存 skipped_reason。phase 不取代 run.status，phase 進度不是證據等級。

run.status 為 QUEUED／RUNNING／CANCEL_REQUESTED／SUCCEEDED／FAILED／CANCELLED。Run 成功是操作按契約結束；outcome_status 可為 SUPPORTED／AMBIGUOUS／INSUFFICIENT_EVIDENCE／FALSIFIED。候選、實證級別及 proof 級別分開保存。預算耗盡而有部分產物時可成功結束操作並記 stop_reason=BUDGET_EXHAUSTED，未完成驗證清楚標示。

## 前後置條件與驗收

| ID | 情境 | 預期 |
|---|---|---|
| AC-04-01 | DRAFT 缺單位且未明確宣告無量綱 | 422 SEMANTIC_PROFILE_INCOMPLETE；不得進 READY |
| AC-04-02 | READY 合法提交→worker→證據→審核 | 每次轉移有 audit/outbox，完整走到 PUBLISHED |
| AC-04-03 | 同 revision 兩人同時核准 | 僅一筆審核交易提交，後者 412 REVISION_CONFLICT |
| AC-04-04 | 已 CANCELLED 的 run 收到遲到完成結果 | 拒絕提交；原產物可讀，狀態不回到 SUCCEEDED |
