# 04｜端到端研究流程

> AXIOM v2.7 設計規格｜文件 ID AX-04｜狀態：待實作、待驗收｜2026-10-20

## 研究與任務的分工

Research 是長期容器；ResearchVersion 固定資料、語意、欄位映射、評估政策、假設、切分、公式集合與研究總 budget。Run 是一次操作，Attempt 是同操作的重試。新資料、修改假設、不同搜尋組態都建立新 ResearchVersion 或新 Run，不改舊證據。僅重試完全相同操作時保留 run_id。

## 研究版本狀態轉移

| 起始 | 操作與前置條件 | 目標 | 拒絕情境 |
|---|---|---|---|
| DRAFT | validate，語意／資料版本完整 | VALIDATING | 缺欄回 422，不啟動搜尋 |
| VALIDATING | 品質檢查完成且無阻擋 | READY | 不通過回 DRAFT，保存報告 |
| READY | 提交 search run，交易預留預算 | QUEUED | 配額不足 429，狀態不變 |
| QUEUED | worker 取得有效租約 | RUNNING | 已取消不得取得新租約 |
| RUNNING | 全部必要子任務終態、凍結評估按政策完成且產物已提交 | REVIEW | 部分失敗則結果可為證據不足，不假報全成功 |
| REVIEW | 獨立審核者依核准政策核准有效EvidenceBundle及PublicationClaim | PUBLISHED | 缺證據／政策、主張不符、撤銷或自我核准均阻擋；不自動釋出摘要 |
| REVIEW | 拒絕，保存 ReviewDecision.decision=REJECT | REVIEW | 重做另建 DRAFT 版本，舊審核不可覆寫 |
| QUEUED / RUNNING | cancel 接受後停止派送、撤銷租約 | CANCELLED | 只有根接受公開取消；請求先進停止中，全部子工作停止確認後版本才CANCELLED；裁決依AX-38 |
| QUEUED / RUNNING | SEARCH排隊超時且未claim，或不可恢復的基礎設施失敗；活躍子樹先停止 | FAILED | 合法歧義／無規律不是基礎設施失敗；PROFILE仍回DRAFT |

目前 /api/v2 不提供暫停／恢復使用者操作；checkpoint 僅供 crash retry。PAUSED 是後續版本保留值，輸入回 INVALID_TRANSITION。CANCELLED／FAILED 版本可建立新 run 前須另建 READY 的新版本；發布不可被重跑覆蓋。PUBLISHED 可附撤銷記錄及最新證據有效性，不直接刪歷史。

## Run phase 與結果

phase 為 PROFILING／FEASIBILITY／RETRIEVING／PLANNING／SEARCHING／FITTING／VALIDATING／FINALIZING；MVP 未啟用記憶或 AI 時直接略過，保存 skipped_phases[{phase,reason}]。phase 不取代 run.status，phase 進度不是證據等級。

run.status 為 QUEUED／RUNNING／CANCEL_REQUESTED／SUCCEEDED／FAILED／CANCELLED。Run 成功是操作按契約結束；Run.outcome_status 在尚未形成研究判定、INGEST／PROFILE／REVOKE 或取消時為 null；SEARCH 完成後可為 SUPPORTED／AMBIGUOUS／INSUFFICIENT_EVIDENCE／FALSIFIED。候選、實證級別及 proof 級別分開保存。預算耗盡而有部分產物時可成功結束操作並記 stop_reason=BUDGET_EXHAUSTED，未完成驗證清楚標示。

## 前後置條件與驗收

| ID | 情境 | 預期 |
|---|---|---|
| AC-04-01 | DRAFT 缺單位且未明確宣告無量綱 | 422 SEMANTIC_PROFILE_INCOMPLETE；不得進 READY |
| AC-04-02 | READY 合法提交→worker→證據→審核 | 每次轉移有 audit/outbox，完整走到 PUBLISHED |
| AC-04-03 | 同 revision 兩人同時核准 | 僅一筆審核交易提交，後者 412 REVISION_CONFLICT |
| AC-04-04 | 已 CANCELLED 的 run 收到遲到完成結果 | 拒絕提交；原產物可讀，狀態不回到 SUCCEEDED |

任務重試與競態見 AX-38，API 行為見 AX-21，研究引用見 AX-47。對實證未達門檻的報告仍可匯出，但不得發布成已驗證知識。

研究狀態改變、凍結、核准與撤銷同交易寫RESEARCH stream；run終態只關其RUN stream。ResearchVersion snapshot的revision只在狀態／可操作前置條件改變時遞增，事件cursor另記每個生命週期事件，不依心跳刷新。

## PROFILE 的取消、失敗與重試

VALIDATING 對應唯一有效 PROFILE 根任務。公開取消依 AX-38 先將 Run 設 CANCEL_REQUESTED；ResearchVersion 保持 VALIDATING，待整樹停止確認後，同交易將 Run 設 CANCELLED、版本回 DRAFT，保存品質報告引用（若已產生），更新 revision 與兩種 stream。不可恢復的 PROFILE 基礎設施失敗同樣終結 Run=FAILED 並將版本回 DRAFT；可恢復錯誤在原 run 建新 attempt，版本保持 VALIDATING。一般品質不通過是操作正常完成、Run=SUCCEEDED、版本回 DRAFT，不能偽裝成基礎設施錯誤。

停止中拒絕再次 validate；回 DRAFT 後，相同輸入可用新 Idempotency-Key／最新 revision 建立新 PROFILE run，舊 key 仍回原操作結果。修改內容需新 ResearchVersion。終態與版本回退持相同 root／研究列鎖；舊 attempt 不得再將版本改為 READY。quality_report_id 指向可讀 Artifact，無報告時為 null。

| ID | 情境 | 預期 |
|---|---|---|
| AC-04-05 | VALIDATING 取消後重送 validate | 停止中409；停止確認後DRAFT，可新建PROFILE，舊attempt不得READY |
| AC-04-06 | PROFILE品質失敗／暫時錯誤／永久錯誤 | 依序SUCCEEDED+DRAFT／重試+VALIDATING／FAILED+DRAFT，保留已有報告 |
| AC-04-07 | 搜尋歧義與未啟用階段 | Run.outcome_status=AMBIGUOUS；skipped_phases保存phase及reason，非FAILED |

## 沒有可評候選或最終預算不足

搜尋沒有合法候選不是基礎設施故障。探索子任務已停止／終態、成本與允許的診斷Artifact已提交後，根Run=SUCCEEDED、outcome_status=INSUFFICIENT_EVIDENCE、stop_reason=NO_VALID_CANDIDATE、dispatch_stage=CLOSED，ResearchVersion由RUNNING進REVIEW供使用者檢視不足報告。Run.diagnostic_artifact_ids指向PROJECT類別且不含final內容的報告；記錄策略拒用／失敗原因、候選數及已用預算。沒有證據就不建立EvidenceBundle，frozen_submission_ids維持空，不預留SealedTest或觀測ledger，不派final VALIDATE。

合法候選存在但凍結前無足夠額度完成必要最終評估時，採相同終止路徑，stop_reason=BUDGET_EXHAUSTED，保留開發產物與未完成驗證清單。skipped_phases記最終評估略過理由；不得將開發分數當獨立final結果。這是狀態轉移表「按政策完成」的明確例外分支，不等待永遠無法建立的空FrozenSubmission，也不放寬凍結包至少一候選的約束。

若凍結／預留已開始，則沿原包／slot終結或保存部分結果，封存狀態依AX-05保守消耗／退役，不以此分支回收資格。沒有有效EvidenceBundle的REVIEW版本不能核准、不能發布，也不建立無證據的ReviewDecision；UI提供不足報告及另建研究版本操作。不可恢復基礎設施錯誤仍Run=FAILED／版本FAILED；使用者取消仍依原取消流程，優先於正常不足終止。

| ID | 情境 | 預期 |
|---|---|---|
| AC-04-08 | 全策略不適用／所有候選非法 | SUCCEEDED＋INSUFFICIENT_EVIDENCE／REVIEW；有診斷、無凍結及盲測消耗 |
| AC-04-09 | 候選存在但final預算不足 | BUDGET_EXHAUSTED；保留開發結果，禁止發布成已驗證知識 |
