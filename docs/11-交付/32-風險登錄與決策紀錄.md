# 32｜風險登錄與決策紀錄

> AXIOM v2.1 整合基線｜文件 ID AX-32｜狀態：設計基線（未實作）｜2026-10-19

## 1. 文件定位與決策摘要

高風險：有限樣本不可識別、搜尋爆炸、LLM 幻覺、資料洩漏、盲測污染、符號證明超時、GPU 供應、授權相容；每項建立 trigger、mitigation、fallback、owner。

**設計原則**：每個規範都要能轉換成可測試的行為、可追溯的證據或明確的工程決策；凡屬目標數字均非已實測結果。

## 2. 章節專屬規格

### 主要風險

| ID | 風險 | 緩解 |
|---|---|---|
| RISK-01 | 過度擬合被誤判為發現 | 盲測、拒答、外插測試 |
| RISK-02 | 記憶負遷移 | no-memory 對照、降權 |
| RISK-03 | LLM 幻覺推導 | AST、獨立驗證、證明核心 |
| RISK-04 | 計算成本失控 | 預算、早停、佇列隔離 |
| RISK-05 | 測試集污染 | 家族隔離與權限隔離 |
| RISK-06 | 敏感資料外傳 | 本地路由、資料分級 |
| RISK-07 | 公式 DSL 擴充破壞相容 | schema 版本、遷移測試 |
| RISK-08 | UI 大數據卡頓 | 降採樣、增量繪圖 |

### ADR 模板

每項決策記錄 ID、背景、選項、決策、理由、影響、回退條件、日期與審核人；先行決策：ADR-001 Django 模組化單體；ADR-002 PostgreSQL+pgvector；ADR-003 公式 AST/DSL；ADR-004 數學驗證與 AI 分離；ADR-005 任務佇列隔離；ADR-006 以 Docker Compose 統一環境：開發於 macOS、架設於 Windows 11 + WSL2（背景：需在兩種平台上可重現地架設同一套服務，且開發與架設不得分歧；選項：各平台宿主直裝／單一 Compose 定義跨平台／雲端開發環境；決策：採單一 Compose 定義，macOS 供開發與基準、Windows WSL2 供實際架設，差異僅以覆寫檔表達；理由：環境可重建、兩平台同構、避免污染宿主、基準數據可互相比較；影響：需維護多架構映像、健康檢查，以及 WSL2 的路徑、換行與資源上限規範；回退條件：Mac 資源不足時改以 WSL2 為主要環境，或需 GPU 直通時改採獨立 Ubuntu 主機）。

### 定期治理

每個里程碑重評風險；高風險項目設具體負責人、預警指標與回退預案。

## 3. 能力分解與詳細規格

### 3.1 階段交付

M0 規格凍結與風險；M1 資料／公式 DSL／驗證；M2 單序列發現；M3 視覺化工作台；M4 記憶與 AI 協作；M5 推演與證明；M6 雙序列；M7 多序列與自動訓練。

**強制規則／例外處理**：每階段以可展示的驗收證據關閉，不以文件完成代替產品完成。

### 3.2 依賴關係

DSL 與驗證先於公式搜尋；基準測試先於策略訓練；經驗品質管理先於微調；單序列驗收先於雙序列；雙序列驗收先於多序列。

**強制規則／例外處理**：關鍵路徑阻塞須升級處理並更新時程。

### 3.3 團隊與責任

產品／研究負責人、數學演算法工程師、Python 後端、Vue 前端、MLOps、DevOps/SRE、QA/資安；小團隊可兼任但不得取消審核分離。

**強制規則／例外處理**：公式證明與證據評級需獨立覆核。

### 3.4 風險與決策

建立 ADR、風險概率×衝擊、緩解、預警、責任人、關閉證據；尚未確定的模型與工具列為待決事項。

**強制規則／例外處理**：高風險項目未有替代方案不得進入正式發布。

## 4. 執行規範與設計檢查點

1. **前置檢查**：啟動「風險登錄與決策紀錄」相關功能前，驗證資料版本、權限、依賴服務、研究模式及資源配額。

2. **核心處理**：依本文件第 2、3 節執行，記錄所有關鍵決策、失敗原因、所採用的假設及每一個中間產物的來源。

3. **完成條件**：輸出不僅有成功結果，也有失敗、部分成功、歧義及不可執行狀態；不得默默回退成看似正常的結果。

4. **品質檢查**：用正常、邊界、異常、對抗、重試、並行與取消情境驗證行為；保留對照測試與審核記錄。

## 6. 失敗情境與降級策略

| 失敗或風險 | 系統反應 | 留存證據 |
|---|---|---|
| 輸入不符合「風險登錄與決策紀錄」要求 | 拒絕執行並提供可修正的欄位錯誤 | 輸入版本、驗證規則、錯誤代碼 |
| 依賴服務中斷或超時 | 有限次重試；超出預算即終止並保存 checkpoint | 服務版本、耗時、重試紀錄 |
| 結果彼此衝突或證據不足 | 保留候選及歧義，不提升證據等級 | 候選集合、反例、驗證集 |
| 資源配額超出 | 中止重運算，保留已完成的可信部分結果 | CPU/GPU 秒、記憶體峰值、任務狀態 |

## 7. 可執行驗收案例

**AC-32-01 正常路徑**：給定完整合法的輸入、固定資料版本與計算預算，執行「風險登錄與決策紀錄」流程，必須產出可追溯的結果與完成狀態。

**AC-32-02 異常路徑**：故意提供缺欄、錯誤型別、超時或不合法狀態，必須得到明確診斷且不得產生已驗證的假結果。

**AC-32-03 重現性**：在固定輸入、版本、隨機種子與執行環境下重跑，輸出應符合預先定義的決定性或容差標準。

**AC-32-04 權限與審核**：未授權角色不得讀取或發布研究資料；審核者能查詢完整證據鏈。
