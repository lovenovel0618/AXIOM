# 30｜里程碑與分階段開發計畫

> AXIOM v2.1 整合基線｜文件 ID AX-30｜狀態：設計基線（未實作）｜2026-10-19

## 1. 文件定位與決策摘要

M0 2–4 週設計與基準；M1 4–8 週可信數學核心；M2 6–10 週單序列搜尋；M3 4–8 週工作台；M4 6–10 週記憶 AI；後續推演與多序列依團隊人力重估。此為初估非承諾。

**設計原則**：每個規範都要能轉換成可測試的行為、可追溯的證據或明確的工程決策；凡屬目標數字均非已實測結果。

## 2. 章節專屬規格

### 里程碑

| 階段 | 核心交付 | 完成閘門 |
|---|---|---|
| M0 需求與數學規範 | DSL、資料契約、測試計畫 | 設計審查通過 |
| M1 基準與可信核心 | 資料匯入、基準、驗證器 | 對抗測試可重現 |
| M2 單序列 MVP | 搜尋、最佳化、圖表工作台 | 基準達預設門檻 |
| M3 記憶與 AI | 經驗檢索、ChatGPT/Ollama | A/B 測得淨收益 |
| M4 推演與學習 | 推導、證明接口、策略模型 | 可信鏈與回歸通過 |
| M5 雙序列 | 相依、互斥、時滯 | 統計測試通過 |
| M6 多序列 | 條件關係、交互作用 | 大規模壓測通過 |

### 每階段步驟

規格凍結 → ADR 審查 → 風險與基準設計 → API/資料契約 → 後端與前端並行 → 數學測試 → 安全與效能測試 → 使用者驗收 → 灰度發布 → 回顧與文件更新。

### 人力與工期

工期需根據團隊人數、算力與基準難度估算；建議至少涵蓋產品、Python 後端、數學/統計、Vue 前端、AI/ML、QA/SRE 職能，可由少數人兼任但需分離驗證責任。

## 3. 能力分解與詳細規格

### 3.1 階段交付

M0 規格凍結與風險；M1 資料／公式 DSL／驗證；M2 單序列發現；M3 視覺化工作台；M4 記憶與 AI 協作；M5 推演與證明；M6 雙序列；M7 多序列與自動訓練。

**強制規則／例外處理**：每階段以可展示的驗收證據關閉，不以文件完成代替產品完成。

### 3.2 依賴關係

DSL 與驗證先於公式搜尋；基準測試先於策略訓練；經驗品質管理先於微調；單序列驗收先於雙序列；雙序列驗收先於多序列。

**強制規則／例外處理**：關鍵路徑阻塞須升級處理並更新時程。

### 3.3 團隊與責任

產品／研究負責人、數學演算法工程師、Python 後端、Vue 前端、MLOps、DevOps/SRE、QA/資安；小團隊可兼任但不得取消審核分離。

**強制規則／例外處理**：公式證明與證據評級需獨立覆核。

### 3.4 風險與決策

建立 ADR、風險概率×衝擊、緩解、預警、責任人、關閉證據；尚未確定的模型與工具列為待決事項。

**強制規則／例外處理**：高風險項目未有替代方案不得進入正式發布。

## 4. 執行規範與設計檢查點

1. **前置檢查**：啟動「里程碑與分階段開發計畫」相關功能前，驗證資料版本、權限、依賴服務、研究模式及資源配額。

2. **核心處理**：依本文件第 2、3 節執行，記錄所有關鍵決策、失敗原因、所採用的假設及每一個中間產物的來源。

3. **完成條件**：輸出不僅有成功結果，也有失敗、部分成功、歧義及不可執行狀態；不得默默回退成看似正常的結果。

4. **品質檢查**：用正常、邊界、異常、對抗、重試、並行與取消情境驗證行為；保留對照測試與審核記錄。

## 6. 失敗情境與降級策略

| 失敗或風險 | 系統反應 | 留存證據 |
|---|---|---|
| 輸入不符合「里程碑與分階段開發計畫」要求 | 拒絕執行並提供可修正的欄位錯誤 | 輸入版本、驗證規則、錯誤代碼 |
| 依賴服務中斷或超時 | 有限次重試；超出預算即終止並保存 checkpoint | 服務版本、耗時、重試紀錄 |
| 結果彼此衝突或證據不足 | 保留候選及歧義，不提升證據等級 | 候選集合、反例、驗證集 |
| 資源配額超出 | 中止重運算，保留已完成的可信部分結果 | CPU/GPU 秒、記憶體峰值、任務狀態 |

## 7. 可執行驗收案例

**AC-30-01 正常路徑**：給定完整合法的輸入、固定資料版本與計算預算，執行「里程碑與分階段開發計畫」流程，必須產出可追溯的結果與完成狀態。

**AC-30-02 異常路徑**：故意提供缺欄、錯誤型別、超時或不合法狀態，必須得到明確診斷且不得產生已驗證的假結果。

**AC-30-03 重現性**：在固定輸入、版本、隨機種子與執行環境下重跑，輸出應符合預先定義的決定性或容差標準。

**AC-30-04 權限與審核**：未授權角色不得讀取或發布研究資料；審核者能查詢完整證據鏈。

## 8. 實作任務分解與交付物

| 順序 | 工作項 | 完成定義 |
|---|---|---|
| 1 | 規格與輸入輸出契約 | 完成 schema、狀態與錯誤定義，審查通過 |
| 2 | 核心流程與依賴整合 | 完成可重現的端到端最小流程 |
| 3 | 邊界與反例測試 | 正常、異常、資源限制及證據不足皆有測試 |
| 4 | 視覺化與運維可見性 | 使用者可理解結果、限制、進度與失敗原因 |
| 5 | 發布審核 | 有版本、驗收紀錄、回滾方案及已知限制 |
