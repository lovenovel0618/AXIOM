# 12｜參數最佳化與數值精度

> AXIOM v2.7 設計規格｜文件 ID AX-12｜狀態：待實作、待驗收｜2026-10-20

## 文件定位與決策摘要

非線性最佳化採多起點與參數界限，避免單次局部最優；報告 Hessian/條件數或 profile likelihood 的可識別性線索；數值不穩定時才提高 mpmath 精度，且保存精度決策原因。

## 章節專屬規格

### 最佳化層級

解析解優先；非線性最小平方法；多起點全域搜尋；有界最佳化；混合離散結構與連續參數分層求解；依參數可識別性選擇正則化或貝氏估計。

### 精度策略

預設 float64；對消、極端尺度、近奇異點啟用 mpmath 任意精度；紀錄精度位數、條件數、溢位/下溢、計算時間；高精度不能補回測量資訊。

### 敏感度

參數 profile likelihood、bootstrap 或可信區間、Jacobian 條件數、Hessian 退化檢查；必要時回報參數組合不可辨識，而非給虛假的精確係數。

## 關鍵技術決策與邊界條件

1. 區分資料精度、參數輸出位數、演算法浮點精度與真實測量準確度，介面必須各自標示。

2. 最適化採多起點初始化與參數約束；記錄收斂訊息、梯度或 Jacobian 條件、重啟次數與失敗點。

3. 使用時間前推切分、blocked CV 或依研究類型選定的 holdout；不能隨機打亂有時間依賴的序列。

4. 精度升級門檻由條件數、消去誤差、近奇異點、對照高精度差異觸發；避免全程高精度造成不必要成本。

以下為預定測試，狀態皆 NOT_RUN；實際證據依 AX-46 登錄。

## 共用規則

版本、錯誤、證據與審查規則見 [AX-48 共用契約與文件治理](<../00-總覽/48-共用契約與文件治理.md>)；本章的專屬限制及驗收條件仍須同時滿足。

FitRun.precision_bits統一以二進位有效精度表示，float64記53；mpmath等工具需顯式轉換其配置單位並記錄實際位元精度，不能把53解讀為53位十進位小數。

## 完整執行快照與重現性

FitRun.execution_manifest_id固定內部ExecutionManifest；preprocessor_artifact_id必填可null，null只代表未做任何學習型前處理，非「遺失」。manifest包含environment digest、input hash、SemanticProfile hash、seed，以及每個plugin的ID／version／code_sha256／完整config／config_sha256；config hash用共用canonical JSON重算。optimizer、容差、initialization、停止條件、數值backend、執行緒及硬體非決定性聲明都入config，禁止只記「least_squares」字串後宣稱可重現。manifest的input_hash對應不含execution_manifest_id自身的canonical TaskInput，避免自參照hash。

固定seed不保證跨硬體bitwise一致。重現先核對檔案／AST／binding／轉換／split／policy／manifest的身分，再依已聲明數值容差比較結果；容差必須預註冊且以canonical單位表達，不能重跑後放寬。浮點常數、參數正規化與Decimal→binary轉換記錄於環境及數值診斷Artifact。fit失敗需區分未收斂、不可識別、數值溢位及取消，不能填假參數或用前一次成功值冒充。

候選排名依預註冊development指標與複雜度；相同分數／複雜度以dsl_identity_hash、canonical parameter_binding_hash穩定破同分，不能用隨機UUID、完成時間或final分數重排。排名與選擇規則亦固定於manifest，搜尋所得最佳只代表本次有限預算探索，不能宣稱全域最優或結構唯一。
