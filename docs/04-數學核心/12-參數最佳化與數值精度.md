# 12｜參數最佳化與數值精度

> AXIOM v2.6 設計規格｜文件 ID AX-12｜狀態：待實作、待驗收｜2026-10-20

## 文件定位與決策摘要

非線性最佳化採多起點與參數界限，避免單次局部最優；報告 Hessian/條件數或 profile likelihood 的可識別性線索；數值不穩定時才提高 mpmath 精度，且保存精度決策原因。

## 章節專屬規格

### 最佳化層級

解析解優先；非線性最小平方法；多起點全域搜尋；有界最佳化；混合離散結構與連續參數分層求解；依參數可識別性選擇正則化或貝氏估計。

### 精度策略

預設 float64；對消、極端尺度、近奇異點啟用 mpmath 任意精度；紀錄精度位數、條件數、溢位/下溢、計算時間；高精度不能補回測量資訊。

### 敏感度

參數 profile likelihood、bootstrap 或可信區間、Jacobian 條件數、Hessian 退化檢查；必要時回報參數組合不可辨識，而非給虛假的精確係數。

## 關鍵技術決策與邊界條件

1. 區分資料精度、參數輸出位數、演算法浮點精度與真實測量準確度，介面必須各自標示。

2. 最適化採多起點初始化與參數約束；記錄收斂訊息、梯度或 Jacobian 條件、重啟次數與失敗點。

3. 使用時間前推切分、blocked CV 或依研究類型選定的 holdout；不能隨機打亂有時間依賴的序列。

4. 精度升級門檻由條件數、消去誤差、近奇異點、對照高精度差異觸發；避免全程高精度造成不必要成本。

## 章節驗收案例

以下為預定測試，狀態皆 NOT_RUN；實際證據依 AX-46 登錄。

| ID | 固定情境／操作 | 預期判定 |
|---|---|---|
| AC-12-01 | 固定 B-LINE 參數與 precision | 逐點在 AX-28 容差內，紀錄 optimizer/seed |
| AC-12-02 | 多起點得到同擬合但不同參數 | 保留多解與退化診斷 |
| AC-12-03 | 提升運算精度但量測精度不變 | 不得提升證據或顯示虛假量測準確度 |
| AC-12-04 | optimizer 不收斂／極點處 NaN | 明確失敗／DOMAIN_VIOLATION，不填 0 |

## 共用規則

版本、錯誤、證據與審查規則見 [AX-48 共用契約與文件治理](<../00-總覽/48-共用契約與文件治理.md>)；本章的專屬限制及驗收條件仍須同時滿足。

FitRun.precision_bits統一以二進位有效精度表示，float64記53；mpmath等工具需顯式轉換其配置單位並記錄實際位元精度，不能把53解讀為53位十進位小數。
