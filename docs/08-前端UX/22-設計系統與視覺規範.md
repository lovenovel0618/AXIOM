# 22｜設計系統與視覺規範

> AXIOM v2.1 整合基線｜文件 ID AX-22｜狀態：設計基線（未實作）｜2026-10-19

## 1. 文件定位與決策摘要

UI 字級與層級：主畫面採 12 欄響應式網格、側欄可收合、數學公式不截斷而可橫向捲動；深淺色模式、色盲安全配色、鍵盤操作、WCAG 2.2 AA 為目標。

**設計原則**：每個規範都要能轉換成可測試的行為、可追溯的證據或明確的工程決策；凡屬目標數字均非已實測結果。

## 2. 章節專屬規格

### 視覺方向

科學研究工作台風格：深淺色雙主題、低干擾中性色、有限語意色（通過／警示／失敗／未驗證）、12 欄響應式格線、可收合側欄、資訊密度可調。

### 排版與公式

Vue 3 + TypeScript + Vite；KaTeX 顯示、MathLive 編輯、MathJax 作特殊排版備援；公式可複製 LaTeX、檢視 AST、縮放、鍵盤導覽。長公式支援折行／水平捲動，禁止裁切。

### 圖表與互動

Plotly.js 優先用於科學曲線、3D、縮放、刷選、殘差；ECharts 用於 KPI 與儀表板；大量點數使用降採樣、WebGL 或後端聚合，保留原始數據下載。

### 無障礙

WCAG 2.2 AA 為目標；鍵盤可操作、焦點可見、圖表文字替代、色盲友善配色、公式語音／MathML 備援；使用者可關閉動畫。

## 3. 能力分解與詳細規格

### 3.1 資訊架構

首頁儀表板、資料集、研究工作台、公式探索器、公式片段庫、推導證明工作台、理論演化圖、基準測試、AI 模型中心、系統管理。

**強制規則／例外處理**：每個主要頁面均有空狀態、載入狀態、失敗狀態與權限不足狀態。

### 3.2 研究工作台

左側資料與研究設定；中央散點／函數／殘差疊圖；右側候選公式、證據與假說；底部執行時間線與工作日誌。

**強制規則／例外處理**：可切換線性／對數軸，顯示採樣域與外插域邊界，不能用平滑線掩蓋離散觀測。

### 3.3 公式呈現

KaTeX 讀取 LaTeX；MathLive 編輯；Plotly 支援縮放、hover、圖層；大型資料採抽樣與視窗化；公式顯示和計算結構保持對應。

**強制規則／例外處理**：每條公式可展開參數、假設、推導鏈、誤差與適用域；複製 LaTeX 與匯出報告。

### 3.4 視覺可信度

觀測點、擬合線、預測區間、外插區間、驗證集及反例使用明確不同視覺語意；色彩不能作為唯一辨識依據。

**強制規則／例外處理**：高風險狀態要有文字標籤；支援鍵盤、縮放、螢幕閱讀器及手機閱讀。

## 4. 關鍵技術決策與邊界條件

1. 公式字體、一般 UI 字體、數據表等寬數字需區分；長公式允許水平捲動與局部放大。

2. 圖表應同時提供數值表、圖例與可匯出資料，確保無法閱讀視覺圖時仍能理解。

3. 驗證狀態以文字與圖示雙重表示，不使用單靠紅綠色的設計。

4. 定義 skeleton、空資料、錯誤、超時、部分完成、證據不足、離線等畫面狀態。

## 6. 失敗情境與降級策略

| 失敗或風險 | 系統反應 | 留存證據 |
|---|---|---|
| 輸入不符合「設計系統與視覺規範」要求 | 拒絕執行並提供可修正的欄位錯誤 | 輸入版本、驗證規則、錯誤代碼 |
| 依賴服務中斷或超時 | 有限次重試；超出預算即終止並保存 checkpoint | 服務版本、耗時、重試紀錄 |
| 結果彼此衝突或證據不足 | 保留候選及歧義，不提升證據等級 | 候選集合、反例、驗證集 |
| 資源配額超出 | 中止重運算，保留已完成的可信部分結果 | CPU/GPU 秒、記憶體峰值、任務狀態 |

## 7. 可執行驗收案例

**AC-22-01 正常路徑**：給定完整合法的輸入、固定資料版本與計算預算，執行「設計系統與視覺規範」流程，必須產出可追溯的結果與完成狀態。

**AC-22-02 異常路徑**：故意提供缺欄、錯誤型別、超時或不合法狀態，必須得到明確診斷且不得產生已驗證的假結果。

**AC-22-03 重現性**：在固定輸入、版本、隨機種子與執行環境下重跑，輸出應符合預先定義的決定性或容差標準。

**AC-22-04 權限與審核**：未授權角色不得讀取或發布研究資料；審核者能查詢完整證據鏈。

## 8. 實作任務分解與交付物

| 順序 | 工作項 | 完成定義 |
|---|---|---|
| 1 | 規格與輸入輸出契約 | 完成 schema、狀態與錯誤定義，審查通過 |
