# 27｜可觀測性備份與故障復原

> AXIOM v2.1 整合基線｜文件 ID AX-27｜狀態：設計基線（未實作）｜2026-10-19

## 1. 文件定位與決策摘要

可觀測性四類：業務指標（發現率）、數學指標（校準/誤差）、系統指標（延遲/記憶體）、成本指標（token/GPU 秒）；恢復演練須包含 DB+MinIO 對應版本。

**設計原則**：每個規範都要能轉換成可測試的行為、可追溯的證據或明確的工程決策；凡屬目標數字均非已實測結果。

## 2. 章節專屬規格

### 可觀測性

OpenTelemetry traces/metrics/logs；Prometheus/Grafana；Sentry；追蹤 run_id、資料版本、公式 hash、模型版本、策略版本、成本與資源消耗。禁止記錄機密原始資料與 API 金鑰。

### 告警

任務排隊時間異常、失敗率、GPU OOM、DB/MinIO 容量、驗證器錯誤、模型回退、訓練資料污染、基準回歸、異常 API 費用。

### 復原

DB PITR、物件版本與校驗、定期演練；checkpoint 恢復長任務；模型與訓練資料可追溯；演練 RPO/RTO 並保留報告。

## 3. 能力分解與詳細規格

### 3.1 效能預算

互動 API 以 p95 延遲與吞吐量驗收；公式搜尋以固定算力下的成功率／耗時衡量；圖形顯示以資料規模與裝置分級驗收。

**強制規則／例外處理**：所有數字先定為目標值，經基準測試後修訂，不假稱已達標。

### 3.2 資源治理

每研究設定 CPU 秒、GPU 秒、記憶體上限、模型 token、候選數、AST 深度、精度升級次數與最長執行時間。

**強制規則／例外處理**：超限後保存 checkpoint、提供部分結果與明確終止原因。

### 3.3 安全與隱私

角色權限、資料分類、秘密管理、上傳檔掃描、公式 DSL 白名單、隔離工作池、外部 AI 出站控制、操作審計。

**強制規則／例外處理**：外部模型不應收到未核准的完整原始資料；所有下載依權限與期限控制。

### 3.4 營運韌性

健康探針、結構化日誌、指標、追蹤、告警、備份、災難復原演練；跨資料庫與物件儲存需一致的恢復點策略。

**強制規則／例外處理**：明訂 RPO/RTO 目標與演練證據，避免只宣稱有備份。

### 3.5 研究倫理

社會與行為資料需避免將相關性說成因果；敏感特徵、樣本偏差、群體公平性及再識別風險納入審核。

**強制規則／例外處理**：可公開研究成果與可公開原始資料是兩種不同授權。

## 4. 執行規範與設計檢查點

1. **前置檢查**：啟動「可觀測性備份與故障復原」相關功能前，驗證資料版本、權限、依賴服務、研究模式及資源配額。

2. **核心處理**：依本文件第 2、3 節執行，記錄所有關鍵決策、失敗原因、所採用的假設及每一個中間產物的來源。

3. **完成條件**：輸出不僅有成功結果，也有失敗、部分成功、歧義及不可執行狀態；不得默默回退成看似正常的結果。

4. **品質檢查**：用正常、邊界、異常、對抗、重試、並行與取消情境驗證行為；保留對照測試與審核記錄。

## 6. 失敗情境與降級策略

| 失敗或風險 | 系統反應 | 留存證據 |
|---|---|---|
| 輸入不符合「可觀測性備份與故障復原」要求 | 拒絕執行並提供可修正的欄位錯誤 | 輸入版本、驗證規則、錯誤代碼 |
| 依賴服務中斷或超時 | 有限次重試；超出預算即終止並保存 checkpoint | 服務版本、耗時、重試紀錄 |
| 結果彼此衝突或證據不足 | 保留候選及歧義，不提升證據等級 | 候選集合、反例、驗證集 |
| 資源配額超出 | 中止重運算，保留已完成的可信部分結果 | CPU/GPU 秒、記憶體峰值、任務狀態 |

## 7. 可執行驗收案例

**AC-27-01 正常路徑**：給定完整合法的輸入、固定資料版本與計算預算，執行「可觀測性備份與故障復原」流程，必須產出可追溯的結果與完成狀態。

**AC-27-02 異常路徑**：故意提供缺欄、錯誤型別、超時或不合法狀態，必須得到明確診斷且不得產生已驗證的假結果。

**AC-27-03 重現性**：在固定輸入、版本、隨機種子與執行環境下重跑，輸出應符合預先定義的決定性或容差標準。

**AC-27-04 權限與審核**：未授權角色不得讀取或發布研究資料；審核者能查詢完整證據鏈。
