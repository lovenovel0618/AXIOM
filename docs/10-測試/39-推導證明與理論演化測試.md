# 39｜推導證明與理論演化測試

> AXIOM v2.7 設計規格｜文件 ID AX-39｜狀態：待實作、待驗收｜2026-10-20

## 文件定位與決策摘要

證明測試包括正確恆等式、缺失前提、域限制、錯誤命題、含除零、近似等價冒充恆等、符號超時；形式化檢查必須在固定工具版本與資源限制下執行。

## 章節專屬規格

### 測試家族

微分積分恆等式、定義域受限等價、奇異點、參數退化、分段不可微、複數/實數分歧、符號化簡超時、形式化證明失敗、反例撤銷。

### 證明狀態

實證與證明分軸：NUMERIC_CHECKED 不要求先於形式化檢查。proof_level=P0/P1/P2，checker_status=NOT_RUN/CHECKED/FAILED/UNKNOWN；timeout 是 UNKNOWN。正式等級只能由受信任 checker 結果與公理政策共同提升，不能由 LLM 手動核准。

### 演化回歸

新增資料推翻舊模型時，舊結論降權但保留歷史；推導圖不得產生沒有來源的孤立「已證明」節點；跨版本引用必須可追溯。

## 章節驗收案例

以下為預定測試，狀態皆 NOT_RUN；實際證據依 AX-46 登錄。

| ID | 固定情境／操作 | 預期判定 |
|---|---|---|
| AC-39-01 | 正確命題但缺必要前提 | 不能標形式化通過 |
| AC-39-02 | 偽造 checker output 或任意程式 | 隔離且拒絕，不接權威證據 |
| AC-39-03 | 近似等價冒充恆等 | 保持數值證據，P0 |
| AC-39-04 | 含承認式／未批准公理的 proof | 受信任策略拒絕，即使工具回成功 |

## 共用規則

版本、錯誤、證據與審查規則見 [AX-48 共用契約與文件治理](<../00-總覽/48-共用契約與文件治理.md>)；本章的專屬限制及驗收條件仍須同時滿足。

正式證明需保存 theorem、完整 imported assumptions、公理清單、checker/library 版本、資源限制、原始輸出與 hash。D-07 未核准前 P2 停用；未完成占位、承認式證明或未批准公理即使工具編譯成功也不能晉級。只有可信 checker 與公理政策都接受才是 CHECKED／P2，不能把任意 exit=0 當證明。
