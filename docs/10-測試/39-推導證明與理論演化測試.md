# 39｜推導證明與理論演化測試

> AXIOM v2.1 整合基線｜文件 ID AX-39｜狀態：設計基線（未實作）｜2026-10-19

## 1. 文件定位與決策摘要

證明測試包括正確恆等式、缺失前提、域限制、錯誤命題、含除零、近似等價冒充恆等、符號超時；形式化檢查必須在固定工具版本與資源限制下執行。

**設計原則**：每個規範都要能轉換成可測試的行為、可追溯的證據或明確的工程決策；凡屬目標數字均非已實測結果。

## 2. 章節專屬規格

### 測試家族

微分積分恆等式、定義域受限等價、奇異點、參數退化、分段不可微、複數/實數分歧、符號化簡超時、形式化證明失敗、反例撤銷。

### 證明狀態

DRAFT → NUMERIC_CHECKED → SYMBOLICALLY_DERIVED → FORMALLY_VERIFIED；FAILED/INCONCLUSIVE 分支保留證據；不得由 LLM 手動將狀態改成 VERIFIED。

### 演化回歸

新增資料推翻舊模型時，舊結論降權但保留歷史；推導圖不得產生沒有來源的孤立「已證明」節點；跨版本引用必須可追溯。

## 3. 能力分解與詳細規格

### 3.1 基準資料集設計

建立簡單解析式、複合式、近似不可辨、噪聲／缺值、奇異點／病態、離散遞迴、動態系統、純隨機無規律、變點及跨域外插等家族。

**強制規則／例外處理**：生成公式、參數與測試答案隔離；新演算法不得讀取 hidden ground truth。

### 3.2 測試切分

訓練／開發／盲測依公式結構、參數區間、資料生成器版本與案例來源隔離；時間序列採前推驗證。

**強制規則／例外處理**：禁止同公式僅換係數後跨越家族盲測界線。

### 3.3 評估指標

結構等價率、候選 Top-k、樣本外 RMSE/MAE、外插風險、覆蓋率、錯誤自信率、拒答品質、計算成本、重現率與記憶增益。

**強制規則／例外處理**：精度測試必須區分測量精度與算術精度；高精度數值吻合不構成一般證明。

### 3.4 品質閘門

單元、屬性、變形、契約、整合、端到端、效能、資安、可存取性、回歸、盲測；形式化證明須檢查完整假設。

**強制規則／例外處理**：嚴重數學錯誤、資料洩漏或證據等級誤標視為阻擋發布。

## 4. 執行規範與設計檢查點

1. **前置檢查**：啟動「推導證明與理論演化測試」相關功能前，驗證資料版本、權限、依賴服務、研究模式及資源配額。

2. **核心處理**：依本文件第 2、3 節執行，記錄所有關鍵決策、失敗原因、所採用的假設及每一個中間產物的來源。

3. **完成條件**：輸出不僅有成功結果，也有失敗、部分成功、歧義及不可執行狀態；不得默默回退成看似正常的結果。

4. **品質檢查**：用正常、邊界、異常、對抗、重試、並行與取消情境驗證行為；保留對照測試與審核記錄。

## 6. 失敗情境與降級策略

| 失敗或風險 | 系統反應 | 留存證據 |
|---|---|---|
| 輸入不符合「推導證明與理論演化測試」要求 | 拒絕執行並提供可修正的欄位錯誤 | 輸入版本、驗證規則、錯誤代碼 |
| 依賴服務中斷或超時 | 有限次重試；超出預算即終止並保存 checkpoint | 服務版本、耗時、重試紀錄 |
| 結果彼此衝突或證據不足 | 保留候選及歧義，不提升證據等級 | 候選集合、反例、驗證集 |
| 資源配額超出 | 中止重運算，保留已完成的可信部分結果 | CPU/GPU 秒、記憶體峰值、任務狀態 |

## 7. 可執行驗收案例

**AC-39-01 正常路徑**：給定完整合法的輸入、固定資料版本與計算預算，執行「推導證明與理論演化測試」流程，必須產出可追溯的結果與完成狀態。

**AC-39-02 異常路徑**：故意提供缺欄、錯誤型別、超時或不合法狀態，必須得到明確診斷且不得產生已驗證的假結果。

**AC-39-03 重現性**：在固定輸入、版本、隨機種子與執行環境下重跑，輸出應符合預先定義的決定性或容差標準。

**AC-39-04 權限與審核**：未授權角色不得讀取或發布研究資料；審核者能查詢完整證據鏈。

| 順序 | 工作項 | 完成定義 |
