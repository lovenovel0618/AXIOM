## 共用資料與錯誤約定

UUID 使用標準 UUID 字串；時間為 UTC RFC 3339，顯示時轉使用者時區。SHA-256 為小寫 64 位十六進位。每個可發布產物包含 schema_version、不可變來源版本、產物 checksum、環境 digest 與產生者。精確數以整數／有理數／十進位字串表示，禁止 JSON NaN／Infinity。

缺失、null、空集合有不同意義：必要值不可用 null 代替；可空欄位須明列；未知指標輸出 null 並附 reason，不能填 0。以環境 digest 固定依賴，seed 只控制支援種子的演算法；非決定性實作需聲明容差與適用硬體。

錯誤 envelope 為 code、message、details、request_id、retryable。details 為欄位／限制的結構化清單，不含秘密。穩定錯誤碼見 AX-21。重試須同時服從任務與研究總預算；未知錯誤不得提升證據級別。

## 版本及變更程序

1. 變更者填寫需求、受影響契約、相容性、遷移及回退條件；不可變產物以新增版本取代覆寫。
2. DSL/schema/API 破壞相容的改動升 major；新增相容能力升 minor；文件文字修正不暗改契約版本。
3. 先修改權威文件與對應 schema，再更新引用章節、驗收 fixture、追溯表與索引。
4. 跑文件驗證工具後重建 MANIFEST；程式實作、正式基準與發布簽核是不同工作，不得以文件檢查代替。

## 文件驗收與產品驗收

文件檢查：本地連結、編號、schema／OpenAPI JSON 可解析、fixture schema 驗證、需求到案例連結、manifest hash。產品驗收：實際執行 AX-46 的各 gate，保存環境、輸入、預期／實際結果、執行者與覆核證據。所有未執行案例皆標示 NOT_RUN。

AC-* 原編號保留以便追溯；原先泛用的正常／異常路徑文字由本輪章節專屬測試取代。共用治理集中本章，避免各章複製成互相分歧的規則。

## v2.3 的契約角色

公開／內部schema_version升為2.0，API為/api/v2，event為2.0；DSL維持1.0。這次修訂含破壞相容的Usage、ObservationSplit與stream欄位，因此不是只改文件版本。v1未部署草案由Git歷史保留，無實際資料遷移／相容服務聲明。

權威公開物件：research-v2；權威內部紀錄：runtime-v2；事件：event-v2；HTTP：openapi-v2。驗證工具必須比對公開DTO與內部投影、文字表格與API雙向覆蓋，以及contract scenario的凍結／取消／切分／串流案例。這些參考裁決仍不能替代真實資料庫交易、worker與瀏覽器產品測試。
