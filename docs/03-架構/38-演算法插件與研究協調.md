# 38｜演算法插件與研究協調

> AXIOM v2.5 設計規格｜文件 ID AX-38｜狀態：待實作、待驗收｜2026-10-20

## 插件、公開回應與內部紀錄

插件 manifest 包含 plugin_id/version、input/output schema_version、資料類型、算子、resource_class、precision_support、determinism、seed_support、timeout_seconds、memory_bytes、checkpoint_version。M2 以線性、多項式與固定諧波為基線，設定依 AX-11。插件無權寫 DB、產生 EvidenceBundle 或發布。

[research-v2.schema.json](<../contracts/research-v2.schema.json>) 定義公開 Run／Attempt DTO；[runtime-v2.schema.json](<../contracts/runtime-v2.schema.json>) 定義 RunRecord／AttemptRecord、BudgetAccount 與 UsageReport。內部取消時間、heartbeat、帳本、父子關係不塞進公開 DTO；公開 API 不回傳 RunRecord。兩份 schema 的共同欄位與投影由文件工具比對。

## 任務樹不變條件

根任務有 parent_run_id=null、root_run_id=id、is_root=true、cancellation_epoch（初始 0）及唯一 BudgetAccount。子任務有 parent_run_id、root_run_id、相同 budget_account_id、is_root=false、root_epoch_at_dispatch。parent 與 root 同租戶、同研究版本；INGEST 根任務無研究版本且不得建立研究子任務。建立子任務時在 root lock 內驗證親代鏈，禁止循環／跨 root 連接。

公開 cancel 只接受根任務；對子任務回 409 CHILD_RUN_NOT_CANCELLABLE，回應授權範圍內的 root_run_id。內部子任務失敗可依策略重試，但不能自行解除祖先取消。根任務只有全部必要子任務終態、無待派子工作且產物提交完成才能成功結束。

## 鎖順序與提交程序

所有派送、領取、產物提交、取消均固定先鎖 root，再按祖先深度鎖 ancestor／run，最後鎖 BudgetAccount；不可反序。根 RUNNING 時可派子任務；取消、FAILED、CANCELLED、SUCCEEDED 或 dispatch_stage=CLOSED 時禁止新增。凍結僅關閉探索派送，並非關閉全部派送；分階段規則如下。

1. 領取 QUEUED run 時建立 AttemptRecord，lease_generation 加一，保存當時 root cancellation_epoch。租約預設 60 秒、15 秒心跳，以 DB 時間判斷。
2. 產物提交攜 run_id、attempt_id、generation、root_epoch_at_dispatch。交易先檢查 root 未取消／終態、root epoch 相同、祖先未取消及產物符合 dispatch_stage，再檢查自身 active attempt／未過期租約及 run 狀態，最後提交產物引用與 outbox。
3. 租約到期重領使自身 generation 加一；舊 attempt 即使 root 未取消仍回 STALE_ATTEMPT。root 已取消或 epoch 不符回 ROOT_CANCELLED，沒有候選、證據、發布或業務 outbox 副作用。
4. 心跳只更新內部 AttemptRecord；不得讓每次心跳改 public Run revision。公開 revision 僅在狀態或可操作前置條件改變時遞增，成本／進度以snapshot重讀與event cursor追蹤，不使 cancel 因心跳永久衝突。

## 根取消與崩潰恢復

cancel 根交易取得同 root lock，若已終態回 RUN_ALREADY_TERMINAL；否則設 CANCEL_REQUESTED、cancel_requested_at、cancellation_epoch 加一並寫事件／取消工作。世代立即阻擋所有舊子任務提交與新派送，逐子任務的 CANCEL_REQUESTED／租約撤銷／停止可異步執行。

supervisor 對本機與遠端受派子工作分別下停止要求，預設 5 秒 grace 後強制終止；不能只殺目前機器程序便聲稱整樹已停。回收器持久化追蹤每個子工作停止／租約到期及資源回收確認。父根只在全部子任務停止確認後才 CANCELLED；失聯節點仍記停止中並告警。回收器重啟根據 DB 的 root epoch 繼續，不依賴 Redis 一次性訊息。

完成交易先持有 root lock 並成功提交，後取消回 409；取消先提交，後任何子完成回 ROOT_CANCELLED。root 成功前已有合法子產物保留可讀，但取消後不再新增有效結果。重做研究建立新版本／run，不把取消根改回 RUNNING。

## BudgetLimit、Reservation、Usage

BudgetLimit 定義 cpu_seconds/gpu_seconds/tokens/memory_bytes/wall_seconds/candidate_limit。BudgetReservation 是尚未完成的 CPU/GPU/token、同時記憶體與候選 slots 預留；BudgetUsage 是累計 cpu_seconds/gpu_seconds/tokens、peak_memory_bytes、elapsed_wall_seconds、candidates_generated、candidates_accepted。排隊新 run 的 Usage 全為零；0 不能當無限額度。

root 和全部子任務共用 BudgetAccount。派送交易檢查 consumed+held 不超出累計限額；記憶體檢查同時有效 reservations，不把歷史峰值再加到預留。elapsed_wall_seconds 由根開始到現在的牆鐘時間，不能把並行子任務耗時相加；peak_memory_bytes 由 supervisor 量測同時存活程序總用量峰值，不能把各 attempt 歷史峰值相加。候選生成計入重試／重複生成成本，accepted 是權威去重後數量。

UsageReport 是獨立計量入口：已授權 supervisor 可為歷史 attempt 回報，允許租約過期或根取消後的真實用量；仍驗證 run/attempt 所有權及報告來源。以 usage_event_id 去重，sequence 單調，傳累計量並用與已確認量的差額入帳；較舊 sequence 忽略、相同 event 不同內容拒絕。不能用此入口提交產物、改成功狀態或發布事件。預留在停止／完成確認後釋放，遲到用量仍記帳；尾端超支標為超支並停止新派送，不抹除成本。

## Checkpoint

Checkpoint 保存輸入／資料／DSL／插件／環境 hash、precision_bits、RNG state、策略進度、累計用量、root epoch 與 checksum。禁止載入不可信 pickle。重試需同資料與相容環境，取得新租約後才可讀已驗證 checkpoint；不能恢復被取消的 root。相容失敗回 CHECKPOINT_INCOMPATIBLE；從頭執行也不能重置帳本。

## 持久化的任務輸入

RunRecord另必填input_artifact_id，指向同租戶、checksum已驗證的不可變任務manifest；公開DTO不包含此欄。manifest至少含run_id、type、research_version_id（INGEST可null）、observation_split_id（非研究操作可null）、schema_version與下表操作欄位；supervisor在派送交易檢查manifest與RunRecord一致，再產有限範圍sandbox輸入，不直接把manifest內部URI與憑證交給插件。

| type | 操作專屬必要輸入 |
|---|---|
| INGEST | upload_session_id、暫存object version及預期sha256 |
| PROFILE | dataset_version_id、semantic_profile、ObservationSplit |
| SEARCH | observation_split_id、只含fit/development的projection_artifact_id、策略版本 |
| FIT | candidate_id、equation_version_id、fit或預註冊fit+development列projection_artifact_id、split_role、fit_row_ids／fit_rows_hash、refit_policy_artifact_id、optimizer／seed |
| VALIDATE | fit_run_id、split_role、observation_split_id；FINAL_TEST另需frozen_candidate_id及submission_id |
| REVOKE | evidence_bundle_id、revocation_id與傳播政策版本 |

同一run重試必須使用相同input_artifact_id／checksum；輸入改變就是新run。manifest形狀依 [task-input-v2.schema.json](<../contracts/task-input-v2.schema.json>)，正反例見 [task-input-v2.examples.json](<../contracts/task-input-v2.examples.json>)；型別、root所屬、projection授權、FitRun／FrozenCandidate及重試輸入checksum仍由可信服務核對。schema完成不代表插件／執行器已實作。

## 搜尋凍結與最終評估的派送界線

RunRecord.dispatch_stage 由根紀錄權威裁決，子紀錄不作判斷來源，公開 DTO 不包含此欄。SEARCH 根初始 SEARCH_OPEN，允許搜尋、FIT 及開發 VALIDATE。凍結前先停止探索並等待探索子任務全部終態；可選的預註冊重擬合也必須完成。持 root lock 原子建立 FrozenSubmission、寫 SubmissionFrozen，再轉 FINAL_ONLY；不能在探索子任務仍可能改寫候選時凍結。

FINAL_ONLY 只允許為該根凍結包派送 FINAL_TEST VALIDATE，必須核對 submission_id、frozen_candidate_id、fit_run_id、sealed_test_id 與 manifest；禁止新增搜尋、FIT、開發 VALIDATE 或修改候選。相同 submission 的故障重試遵守 AX-05，一般租約重試保留 run_id／輸入。FINAL_ONLY 接受相符最終評估產物及可信協調器的證據彙整；拒絕遲到探索產物。所有必要最終子任務終態且彙整完成後，根完成交易才設 CLOSED，與 SUCCEEDED／FAILED 及研究轉移一併提交。取消立即設 CLOSED 並遞增 epoch；既有最終子任務同樣被隔離。

非 SEARCH 根不經凍結，RUNNING 時維持 SEARCH_OPEN，終態或取消設 CLOSED；PROFILE 的版本回退依 AX-04。dispatch_stage 不取代 status／epoch／租約檢查，任何一項無效仍拒絕提交。

| ID | 情境 | 預期 |
|---|---|---|
| AC-38-11 | 凍結後派最終VALIDATE與新FIT | 相符凍結評估允許；FIT拒絕DISPATCH_STAGE_VIOLATION |
| AC-38-12 | 探索子任務未完成即凍結，或凍結後遲到候選 | 前者409；後者拒絕，不能改FrozenSubmission |
| AC-38-13 | FINAL_ONLY期間取消，評估稍後提交 | epoch檢查拒絕，全部停止後才根CANCELLED |

## 最終任務的唯一派送與固定域

FINAL_ONLY派送前必須依AX-43取得FinalEvaluationSlot；同提交／候選／metric的重複派送讀回既有run_id，不能新建不同run繞過結果唯一性。slot建立、run／manifest、預留與outbox在root鎖及觀測ledger鎖順序內完成；既有slot重播不重複預留。所有插件輸入的domain與ResearchVersion固定值相符，PROFILE manifest攜相同domain；其他任務沿不可變版本解析，不能以自己產生的AST縮域。

涉及封存預留／槽位時，全域鎖順序依AX-43細化為root→ancestor/run→SealedTest→排序ExposureLedger→FinalEvaluationSlot→BudgetAccount，不可先鎖預算再取得觀測或slot鎖。任務建立與slot引用的UUID可在交易前產生，FK於同交易提交時驗證；有向引用不能要求先暴露半成品run。
