# 38｜演算法插件與研究協調

> AXIOM v2.2 設計規格｜文件 ID AX-38｜狀態：待實作、待驗收｜2026-10-19

## 插件協定

插件 manifest 必填 plugin_id、version、input_schema_version、output_schema_version、supported_data_types、operators、resource_class、precision_support、determinism、seed_support、timeout_seconds、memory_bytes、checkpoint_version。determinism 為 EXACT／TOLERANCE／NONDETERMINISTIC；後兩者附比較方法。插件只輸出候選／診斷，不能直接寫權威 DB 或發布證據。

M2 三策略為線性最小平方、2～3 次多項式、固定諧波字典；每個策略宣告適用條件與上限。非線性符號迴歸是選配策略，不影響三策略基線可驗收性。插件必須先通過 AST、資源限制及惡意輸入測試才可啟用。

## 任務、租約與舊執行者隔離

權威狀態與租約在 PostgreSQL，Redis 僅通知。Run 包含 status、revision、active_attempt_id、lease_generation、cancel_requested_at、budget_account_id。Attempt 包含 worker_id、generation、lease_expires_at、heartbeat_at、checkpoint_id、開始／結束時間及實際成本。

1. worker 以資料庫交易領取 QUEUED run，generation 加一並建立 attempt。規格預設租約 60 秒、心跳每 15 秒；使用 DB 時間判定有效性，屬可調組態。
2. 心跳與所有提交都須帶 run_id、attempt_id、generation；提交交易鎖定 run，只有目前租約未過期、active attempt 相符、generation 相等且未取消才可寫權威產物。
3. 租約過期由回收器建立新 attempt，generation 再加一；舊 worker 即使恢復也收到 STALE_ATTEMPT，不能寫候選、事件或最終結果。舊 worker 已消耗成本仍列入總帳。
4. 產物先置暫存，再在有效租約交易中綁定引用與 outbox；舊 attempt 的孤兒暫存經寬限期清理。
5. 預設最多 3 次 attempts；只重試 retryable 的基礎設施錯誤。非法 AST、域錯誤與配額不足不無限重試。

## 取消與完成競態

取消 API 在同一 run row lock 交易中，對 QUEUED 直接 CANCELLED；對 RUNNING 設 CANCEL_REQUESTED、generation 加一，撤銷舊提交權並通知 supervisor 終止子程序。停止確認後才設 CANCELLED；取消請求成功不代表程序已停止。supervisor 終止子程序的預設 grace 為 5 秒，超時強制停止並記錄。

若完成交易先提交，cancel 回 409 RUN_ALREADY_TERMINAL；若取消交易先提交，完成交易必須失敗，不能兩者皆成功。終態不能回到 RUNNING。取消後尚未回收的資源仍計成本；UI 顯示停止中直到確認，不假報已釋放。

## Checkpoint 與預算

Checkpoint 包含 run／attempt、輸入版本與 hash、插件／DSL／環境 digest、精度、RNG state、策略進度、累計成本與 checksum；序列化為核准 JSON／陣列格式，禁止載入不可信 pickle。只有版本、輸入與執行環境相容且 checksum 正確才續跑；不相容時明確從頭執行，仍保留已耗帳本。

新工作派送前以資料庫交易預留預算；並行策略不能各自讀 remaining 後超賣。CPU／GPU／token 使用量逐 attempt 回報、按唯一 usage_event_id 去重，預留在完成或取消確認後釋放。達上限停止新派送並終止現有工作；尾端超支單獨列報，不承諾可瞬時精確停止。
