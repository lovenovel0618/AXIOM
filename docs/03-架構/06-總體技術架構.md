# 06｜總體技術架構

> AXIOM v2.1 整合基線｜文件 ID AX-06｜狀態：設計基線（未實作）｜2026-10-19

## 1. 文件定位與決策摘要

部署採前端 Nginx、Django ASGI、PostgreSQL、Redis、MinIO、Celery worker、研究協調器、LLM gateway、隔離數學執行器；Lean 4 可選獨立容器。服務間只開必要連線。

**設計原則**：每個規範都要能轉換成可測試的行為、可追溯的證據或明確的工程決策；凡屬目標數字均非已實測結果。

## 2. 章節專屬規格

### 部署拓樸

```mermaid
flowchart TB
 U[Vue3 + TypeScript 研究工作台]-->N[Nginx / HTTPS]
 N-->D[Django + DRF API]
 D-->PG[(PostgreSQL + pgvector)]
 D-->R[(Redis)]
 D-->S[(S3/MinIO)]
 D-->Q[任務佇列與工作流協調]
 Q-->W1[特徵/搜尋 CPU Worker]
 Q-->W2[最佳化/高精度 Worker]
 Q-->W3[GPU/AI Worker]
 Q-->W4[符號/證明隔離 Worker]
 W3-->LLM[ChatGPT API / Ollama]
 W1-->PG
 W2-->S
 W4-->PG
```

### 設計原則

模組化單體 Django 管理身份、專案、資料、研究與 API；計算工作池獨立擴展。將公式 DSL、證據、實驗事件與模型版本視為長期穩定契約。CPU/GPU 工作分離，禁止 HTTP request 同步執行長時間公式搜尋。

### 一致性與容錯

資料庫保存狀態與索引，物件儲存保存大資料；工作事件採冪等鍵與重試退避；輸出物件先上傳再以交易登錄；研究結果可從 checkpoint 恢復。

### 技術取捨

Django/DRF 便於資料治理與管理介面；Celery + Redis 適合首版，複雜長時工作流可評估 Temporal；pgvector 首版足夠，超大規模再評估專用向量服務；MinIO 為自架選項，雲端可使用相容 S3 儲存。

## 3. 能力分解與詳細規格

### 3.1 分層與部署原則

Vue SPA 與 Django API 分離；研究編排器負責任務與策略；Python 計算工作池執行搜尋；隔離證明服務與 LLM gateway；PostgreSQL 保存權威資料，MinIO 保存大物件。

**強制規則／例外處理**：LLM 不可直接操作資料庫或宿主作業系統；長時間計算不得阻塞 HTTP worker。

### 3.2 計算工作池

分 CPU 短任務、CPU 重任務、GPU 任務、符號證明任務；依計算預算、資料敏感等級及演算法需求派送。

**強制規則／例外處理**：排程器必須提供優先級、超時、取消、重試、租約、檢查點與重複任務去重。

### 3.3 版本與依賴

服務 API、公式 DSL、資料 schema、事件 schema、演算法插件與模型權重各自版本化；跨服務契約採向後相容與遷移窗口。

**強制規則／例外處理**：升級時使用契約測試、影子流量與回滾程序。

### 3.4 擴充與隔離

研究租戶、資料空間、權限與配額隔離；外部 AI 模型透過統一 Gateway；數學運算只能在安全執行器內。

**強制規則／例外處理**：高風險輸入、模型生成內容和上傳檔案均視為不可信。

## 4. 執行規範與設計檢查點

1. **前置檢查**：啟動「總體技術架構」相關功能前，驗證資料版本、權限、依賴服務、研究模式及資源配額。

2. **核心處理**：依本文件第 2、3 節執行，記錄所有關鍵決策、失敗原因、所採用的假設及每一個中間產物的來源。

3. **完成條件**：輸出不僅有成功結果，也有失敗、部分成功、歧義及不可執行狀態；不得默默回退成看似正常的結果。

4. **品質檢查**：用正常、邊界、異常、對抗、重試、並行與取消情境驗證行為；保留對照測試與審核記錄。

## 6. 失敗情境與降級策略

| 失敗或風險 | 系統反應 | 留存證據 |
|---|---|---|
| 輸入不符合「總體技術架構」要求 | 拒絕執行並提供可修正的欄位錯誤 | 輸入版本、驗證規則、錯誤代碼 |
| 依賴服務中斷或超時 | 有限次重試；超出預算即終止並保存 checkpoint | 服務版本、耗時、重試紀錄 |
| 結果彼此衝突或證據不足 | 保留候選及歧義，不提升證據等級 | 候選集合、反例、驗證集 |
| 資源配額超出 | 中止重運算，保留已完成的可信部分結果 | CPU/GPU 秒、記憶體峰值、任務狀態 |

## 7. 可執行驗收案例

**AC-06-01 正常路徑**：給定完整合法的輸入、固定資料版本與計算預算，執行「總體技術架構」流程，必須產出可追溯的結果與完成狀態。

**AC-06-02 異常路徑**：故意提供缺欄、錯誤型別、超時或不合法狀態，必須得到明確診斷且不得產生已驗證的假結果。

**AC-06-03 重現性**：在固定輸入、版本、隨機種子與執行環境下重跑，輸出應符合預先定義的決定性或容差標準。

**AC-06-04 權限與審核**：未授權角色不得讀取或發布研究資料；審核者能查詢完整證據鏈。
