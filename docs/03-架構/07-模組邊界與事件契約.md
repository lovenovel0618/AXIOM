# 07｜模組邊界與事件契約

> AXIOM v2.1 整合基線｜文件 ID AX-07｜狀態：設計基線（未實作）｜2026-10-19

## 1. 文件定位與決策摘要

事件至少含 event_id、schema_version、research_id、run_id、occurred_at、actor、payload_hash；處理端採冪等，失敗進死信佇列；事件 payload 不包含完整原始數據。

**設計原則**：每個規範都要能轉換成可測試的行為、可追溯的證據或明確的工程決策；凡屬目標數字均非已實測結果。

## 2. 章節專屬規格

### 核心服務

Data Intake、Semantic Profiler、Feature Extractor、Feasibility、Experience Retrieval、Research Planner、Equation Search、Fragment Composer、Optimizer、Validator、Derivation、Proof Gateway、Evidence Ledger、Knowledge Graph、Training Pipeline、Report Service。

### 輸入輸出契約

每個模組輸入包含 project_id、dataset_version、run_id、budget、seed、precision_policy；輸出包含 artifact_uri、schema_version、status、warnings、provenance、metrics。所有模型候選必須有 canonical_ast_hash 與 domain_constraints。

### 事件規範

DatasetIngested、FeaturesReady、HypothesisProposed、CandidateFound、ValidationCompleted、CounterexampleFound、ExperiencePromoted、TheoryRevised、ModelReleased。事件須具備 event_id、occurred_at、correlation_id、producer_version。

### 可信邊界

LLM 只能輸出結構化假說及搜尋建議；數學執行器不接受未驗證任意 Python；驗證器必須獨立於候選生成器；形式化證明僅信任證明核心結果。

## 3. 能力分解與詳細規格

### 3.1 分層與部署原則

Vue SPA 與 Django API 分離；研究編排器負責任務與策略；Python 計算工作池執行搜尋；隔離證明服務與 LLM gateway；PostgreSQL 保存權威資料，MinIO 保存大物件。

**強制規則／例外處理**：LLM 不可直接操作資料庫或宿主作業系統；長時間計算不得阻塞 HTTP worker。

### 3.2 計算工作池

分 CPU 短任務、CPU 重任務、GPU 任務、符號證明任務；依計算預算、資料敏感等級及演算法需求派送。

**強制規則／例外處理**：排程器必須提供優先級、超時、取消、重試、租約、檢查點與重複任務去重。

### 3.3 版本與依賴

服務 API、公式 DSL、資料 schema、事件 schema、演算法插件與模型權重各自版本化；跨服務契約採向後相容與遷移窗口。

**強制規則／例外處理**：升級時使用契約測試、影子流量與回滾程序。

### 3.4 擴充與隔離

研究租戶、資料空間、權限與配額隔離；外部 AI 模型透過統一 Gateway；數學運算只能在安全執行器內。

**強制規則／例外處理**：高風險輸入、模型生成內容和上傳檔案均視為不可信。

## 4. 執行規範與設計檢查點

1. **前置檢查**：啟動「模組邊界與事件契約」相關功能前，驗證資料版本、權限、依賴服務、研究模式及資源配額。

2. **核心處理**：依本文件第 2、3 節執行，記錄所有關鍵決策、失敗原因、所採用的假設及每一個中間產物的來源。

3. **完成條件**：輸出不僅有成功結果，也有失敗、部分成功、歧義及不可執行狀態；不得默默回退成看似正常的結果。

4. **品質檢查**：用正常、邊界、異常、對抗、重試、並行與取消情境驗證行為；保留對照測試與審核記錄。

## 6. 失敗情境與降級策略

| 失敗或風險 | 系統反應 | 留存證據 |
|---|---|---|
| 輸入不符合「模組邊界與事件契約」要求 | 拒絕執行並提供可修正的欄位錯誤 | 輸入版本、驗證規則、錯誤代碼 |
| 依賴服務中斷或超時 | 有限次重試；超出預算即終止並保存 checkpoint | 服務版本、耗時、重試紀錄 |
| 結果彼此衝突或證據不足 | 保留候選及歧義，不提升證據等級 | 候選集合、反例、驗證集 |
| 資源配額超出 | 中止重運算，保留已完成的可信部分結果 | CPU/GPU 秒、記憶體峰值、任務狀態 |

## 7. 可執行驗收案例

**AC-07-01 正常路徑**：給定完整合法的輸入、固定資料版本與計算預算，執行「模組邊界與事件契約」流程，必須產出可追溯的結果與完成狀態。

**AC-07-02 異常路徑**：故意提供缺欄、錯誤型別、超時或不合法狀態，必須得到明確診斷且不得產生已驗證的假結果。

**AC-07-03 重現性**：在固定輸入、版本、隨機種子與執行環境下重跑，輸出應符合預先定義的決定性或容差標準。

**AC-07-04 權限與審核**：未授權角色不得讀取或發布研究資料；審核者能查詢完整證據鏈。
