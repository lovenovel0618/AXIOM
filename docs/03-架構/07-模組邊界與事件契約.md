# 07｜模組邊界與事件契約

> AXIOM v2.3 設計規格｜文件 ID AX-07｜狀態：待實作、待驗收｜2026-10-19

## 文件定位與決策摘要

事件 envelope 完全依 AX-21／event-v2 schema；actor 由對應 audit 記錄保存，不另在 envelope 發明必填欄位。處理端採冪等，失敗進死信佇列；payload 不包含完整原始數據。

## 章節專屬規格

### 核心服務

Data Intake、Semantic Profiler、Feature Extractor、Feasibility、Experience Retrieval、Research Planner、Equation Search、Fragment Composer、Optimizer、Validator、Derivation、Proof Gateway、Evidence Ledger、Knowledge Graph、Training Pipeline、Report Service。

### 輸入輸出契約

模組依其操作接受 AX-47 對應物件：run_id、research_version_id（INGEST 可 null）、固定資料版本、budget、seed 與環境。SEARCH 沒有必填 equation_version_id；FIT／VALIDATE 才需要。輸出是 Candidate／FitRun／ValidationRun 等領域物件與 checksum 產物，公式身分使用 AX-10 的 identity_hash，不另設 canonical_ast_hash 別名。

### 事件規範

事件名稱、payload、序號與 outbox 規範統一依 AX-21；不另設別名。所有事件使用 occurred_at、trace_id、producer_version、run_id 與每 run sequence。

### 可信邊界

LLM 只能輸出結構化假說及搜尋建議；數學執行器不接受未驗證任意 Python；驗證器必須獨立於候選生成器；形式化證明僅信任證明核心結果。

## Solver／Evaluator 的實際資料隔離

可信 intake 在切分後產生不同物件：SolverInput 只含 fit/development 觀測，EvaluatorInput 含封存 final 與私有真值。兩者 key、bucket policy 與憑證分離。一般 solver sandbox 無 DB／原始 bucket／Evaluator 憑證，由可信 supervisor 以唯讀受限輸入交付；不能因總原檔存有全部列便把完整 DatasetVersion URI 或廣域 MinIO key 交給 Solver。final 評估另以 Evaluator 身分啟動獨立 sandbox。trusted supervisor 可管理派送，但不把其廣域憑證繼承進插件程序。
