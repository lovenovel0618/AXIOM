## 交付包必備
需求規格、ADR、資料字典、API 契約、測試報告、效能報告、資安報告、部署拓樸、Runbook、模型版本、授權清單、已知限制、回滾計畫與簽核紀錄。所有報告需標示測試環境、日期、版本與負責人。

## 工程落地細則與邊界驗收

### 補充規格 1

每一 gate 的測試輸入、預期輸出、實際輸出、執行者、執行時間、環境版本與證據連結必須保存。

**驗收方法**：建立可重現的測試案例，固定輸入版本與環境，記錄正常結果、錯誤結果、例外診斷及回滾證據。審核者應能追溯結果來源，而不是只看到成功提示。

### 補充規格 2

數學 gate 必須有對抗資料、純隨機資料與歧義資料；測試不能只涵蓋容易成功的合成正例。

**驗收方法**：建立可重現的測試案例，固定輸入版本與環境，記錄正常結果、錯誤結果、例外診斷及回滾證據。審核者應能追溯結果來源，而不是只看到成功提示。

### 補充規格 3

證明 gate 的發布條件是受信任的 proof checker 確認且完整保存前提；數值驗證不能替代形式化證明。

**驗收方法**：建立可重現的測試案例，固定輸入版本與環境，記錄正常結果、錯誤結果、例外診斷及回滾證據。審核者應能追溯結果來源，而不是只看到成功提示。

### 補充規格 4

發布前執行故障演練：終止 worker、斷開 MinIO、Redis 重啟、外部 API 超時與前端 SSE 重連，驗證恢復路徑。

**驗收方法**：建立可重現的測試案例，固定輸入版本與環境，記錄正常結果、錯誤結果、例外診斷及回滾證據。審核者應能追溯結果來源，而不是只看到成功提示。

## 需求與證據追溯格式

每筆驗收記錄至少包含：requirement_id、document_id、gate_id、test_id、release_version、environment_digest、dataset_hash、expected、actual、result、evidence_uri、executor、reviewer、executed_at。`result` 僅允許 PASS／FAIL／BLOCKED／NOT_RUN；尚未執行不能預填 PASS。

| Gate | 最低可審查案例 | 預期證據 |
|---|---|---|
| G1 | 將每個 MUST 需求連至驗收案例 | 無孤立需求的追溯表與審核紀錄 |
| G2 | 白噪聲、近似等價候選、極點附近資料、偽證明 | 拒答／歧義、數值診斷、checker 原始輸出 |
| G3 | 停用記憶對照、敏感研究禁止外送 | 同版基準差異、路由決策與遮蔽後稽核 |
| G4 | 還原 DB 與物件快照、遷移失敗回滾 | checksum 比對、版本關係及恢復耗時 |
| G5 | 跨租戶存取、惡意 AST、worker 外網請求 | 拒絕紀錄、隔離測試及權限矩陣 |
| G6 | 四候選、長公式、10 萬點、窄螢幕、純鍵盤 | 各尺寸證據、互動追蹤與可存取性檢核 |
| G7 | worker／Redis／MinIO 故障及 SSE 重連 | 告警、復原結果、run 無重複副作用 |

### 簽核與回退

發布候選凍結程式、模型、DSL、資料 schema、組態與依賴版本；QA 彙整 gate 結果，由各責任角色覆核證據。數學誤報、任意程式執行、越權與證據不可追溯不得以一般已知限制放行。其他延期項目記錄影響、責任人、期限與核准人，且需先修改範圍與相應驗收基線。

回退包包含前版映像與組態、可恢復資料快照、遷移相容範圍、任務暫停／排空程序及恢復後驗證步驟。若資料遷移無法逆轉，必須先演練從快照還原，不可僅將映像切回前版就宣稱可回滾。本文件是發布規格，目前沒有產品測試或簽核完成紀錄。
