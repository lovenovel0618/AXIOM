## 契約版本與範圍

本輪包含破壞相容欄位修正，因此公開資源 schema_version=2.0、HTTP /api/v2、事件 schema_version=2.0；DSL 仍 1.0，觀測政策與 metric_version 為 2.0。v1 是未部署草案，歷史保留在 Git；不宣稱已提供 v1 相容服務或已執行資料遷移。

[research-v2.schema.json](<../contracts/research-v2.schema.json>) 為公開資源／共用值物件；[runtime-v2.schema.json](<../contracts/runtime-v2.schema.json>) 為可信服務內部資料，禁止直接用作 HTTP 回應。各資源共用 id/tenant_id/schema_version/created_at；UUID 與 UTC RFC3339，shape 通過後仍須租戶、關係、狀態及數學語意驗證。

|---|---|---|
| Artifact | owner、URI、sha256、size、media_type、status | 同租戶 registry，不覆寫內容，讀取查 ACL／撤銷 |
| Dataset／DatasetVersion | 名稱與 owner／dataset_id、artifact_id、URI/hash、format、row_count、status | 原始檔不可變，AVAILABLE 才可研究 |
| Research／ResearchVersion | 名稱與 owner／固定資料、semantic_profile、observation_split、budget、purpose、status、revision | 內容改動另建版本；狀態、事件 cursor 與結果引用可變 |
| ObservationSplit | id、dataset_version_id、三區 row IDs、gap/lookback/horizon、seed、時間／群組欄、digest、splitter_version、封存引用 | 單題內觀測切分，三區不交疊；政策見 AX-28 |
| BenchmarkPartition | case/family/source_group→TRAIN/DEVELOPMENT/SEALED_TEST、generator版本、seed manifest hash | 題目級隔離，僅評估管理角色讀，不下放 Solver |
| SealedTest | observation_split／benchmark 引用、final rows/protocol hash、state、submission_id | AVAILABLE→RESERVED→CONSUMED／RETIRED，同一身分不可換研究後重置 |
| Run／Attempt（公開） | 操作型別、狀態、phase、revision、active attempt、event cursor、BudgetUsage、reservations／租約顯示資訊 | 不暴露內部帳本識別與控制欄位；revision是控制版本，無直接寫入端點 |
| RunRecord／AttemptRecord（內部） | 公開資料加 parent/root/account/epoch/input_artifact_id／heartbeat/start/finish/usage | 公開 DTO 是顯式 allowlist 投影，私有欄禁止洩漏；權威見 AX-38 |
| BudgetLimit／BudgetReservation／BudgetUsage | 限額／held 額度／實際累計與峰值 | Usage 可全零；父子共用帳本，量測口徑見 AX-38 |

| Candidate | search_run、equation_version、來源、development rank、fit/validation refs | 同結構候選去重，仍可有多個 FitRun |
| FitRun | run、equation/data/split、split_role、parameters、optimizer、precision_bits | 有限十進位參數恰覆蓋 DSL parameters，precision_bits 指二進位有效精度 |

| FrozenSubmission | research_version、sealed_test、排序 FrozenCandidate IDs、metric_version、snapshot_hash、status | 一次最終提交，凍結 hash 包含全部固定候選與協定 |
| ValidationRun | fit/split/split_role、frozen_candidate_id、metric_version、metrics、coverage、E/P/outcome、artifact | FINAL_TEST 必須引用 FrozenCandidate；開發驗證可 null |
| EvidenceBundle | research_version、validation/proof refs、status、revision | 至少一筆有效證據，不能只檢查 id 非空 |

## 觀測切分的建立與唯讀投影

POST CreateResearchVersion 接受 observation_split（ObservationSplitRequest），只含使用者可提出的 row IDs 與政策欄位；伺服器先確認 dataset_version_id 等於研究資料、row IDs 有效且分區不重疊，再產生 ObservationSplit.id、row_ids_hash 及封存引用。客戶端不能指定 sealed_test_id 或自行宣告 BenchmarkPartition 身分。

正式基準由可信 Generator/Evaluator 註冊 BenchmarkPartition／SealedTest，ResearchVersion 只引用；一般自有資料可有 SealedTest 但 benchmark_partition_id/case_id 為 null。重用同來源與 final rows/protocol 必須查既有 sealed identity ledger，不以新 ResearchVersion 避開消耗。私人 seed/ground truth 不送 Solver，schema 本身不是讀取授權。

## 凍結與評估不變條件

FrozenCandidate.fit_run_id 必須屬 Candidate.fit_run_ids，並引用相同 equation/data/observation split；parameters 必須等於該 FitRun 的完整參數副本，parameter_binding_hash 以名稱排序、十進位去冗餘零後的 JSON 算 SHA-256。DSL identity_hash 與 EquationVersion 相同，環境與來源不能換。

FrozenSubmission.snapshot_hash 由 server 對 research_version_id、sealed_test_id、metric_version 與按 development_rank 排序的 FrozenCandidate 完整快照（不含可變 status）做 canonical JSON SHA-256。sealed row hash／protocol hash 經 SealedTest 固定引用；改任一候選、fit、binding、rank 或協定均是新提交，已消耗測試不可再評。真正結構／參數／預測三種判定以 AX-28 為準。

Artifact 引用物件的 URI/hash 是 registry 的唯讀投影；跨租戶引用、缺檔、hash不符、已撤銷皆阻擋發布。ResearchVersion snapshot 附 evidence_bundle_ids/frozen_submission_ids/review_ids/published_artifact_ids/quality_report_id/current_event_cursor，支援重開與串流補發，不洩漏內部 RunRecord。

## Canonical快照細節

ObservationSplit.row_ids_hash = SHA-256(canonical JSON {fit,development,final_test,gap_rows,lookback_rows,horizon_rows})，保留已固定的列順序，JSON key排序／無空白／UTF-8。row_ids_hash由server產生，不接受客戶端自行填入；GROUPED_ROWS的群組digest另由真實group欄重算驗證。

SealedTest.source_content_sha256保存來源內容hash；相同source_content_sha256、不可變case身分、final_rows_hash與protocol_hash即同一封存身分，不因Dataset容器ID改變。Final提交的snapshot_hash輸入鍵精確為research_version_id、sealed_test_id、metric_version、frozen_candidates；後者是按development_rank排序的FrozenCandidate完整物件列表。references與hash全部檢查後才可從AVAILABLE原子預留SealedTest，拒絕空提交包。

## v2.4 草案欄位補充

公開／runtime／OpenAPI仍為未部署的2.0契約，本文件版次2.4不代表另增HTTP major。Run必填可null的outcome_status與skipped_phases；ResearchVersion必填結果引用及可null的quality_report_id。FitRun增加fit_row_ids／fit_rows_hash／refit_policy_artifact_id，split_role限制FIT／FIT_DEVELOPMENT；同樣欄位必須存在FIT TaskInput。跨物件列集合、hash、預註冊時間與授權由可信服務驗證，非僅schema形狀驗證。runtime RunRecord新增dispatch_stage，公開DTO禁止此欄。

封存的RESERVED／CONSUMED／RETIRED交易、同提交恢復、不可重新取得曝光資格及部分結果唯一性依AX-05；派送與提交階段依AX-38。重擬合的列集合與指標解釋依AX-28。拒絕審核值一律REJECT，不使用REJECTED。

ResearchVersion.refit_policy_artifact_id必填且可null，非null時對應建立版本時伺服器保存的RefitPolicyRequest快照Artifact。此引用屬固定研究設定；FitRun的聯集重擬合政策必須與其相同。

## v2.5 權限、域與評估關聯

公開／runtime／事件仍為未部署2.0草案。ResearchVersion.domain必填ResearchDomain並固定，PROFILE TaskInput亦保存相同域；Artifact.access_class必填且不可由客戶端降級。ValidationRun.submission_id必填可null，FINAL_TEST必非null且與frozen_candidate_id共同引用提交成員，開發評估兩者均null。FinalEvaluationSlot只存在runtime schema，不作HTTP回應，保存跨run去重的唯一評估槽位。SealedTest新增final_observation_tokens／final_lineage_tokens／exposure_fingerprint_version；這些均為Evaluator私有資料，無普通讀取端點，形狀不代表授權。

觀測token的HMAC與穩定來源政策依AX-05，跨提交競態及唯一鍵依AX-43；逐資源封存權限依AX-26，研究域依AX-10。修改來源檔hash、列號、protocol或Dataset容器不代表final觀測重新未知。
