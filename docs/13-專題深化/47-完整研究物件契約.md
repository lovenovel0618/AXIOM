# 47｜完整研究物件契約

> AXIOM v2.1 整合基線｜文件 ID AX-47｜狀態：設計基線（未實作）｜2026-10-19

## 權威研究物件
研究是一個不可變版本鏈：Research → DatasetVersion → SemanticProfile → FeatureSet → HypothesisSet → SearchRun → CandidateEquation → FitRun → ValidationRun → EvidenceBundle → ReviewDecision → PublishedArtifact。任何下游變更都產生新版本，不回寫舊證據。

## 必要欄位與限制
| 物件 | 核心欄位 | 不變條件 |
|---|---|---|
| DatasetVersion | dataset_id、hash、schema、source、license、units、precision | 原始資料不可原地改寫 |
| Research | purpose、domain、constraints、budget、split_policy、owner | 發布後的研究假設不可偷偷修改 |
| Equation | canonical_ast、dsl_version、domain、parameters、units | LaTeX 不是唯一權威表示 |
| FitRun | data_version、equation_version、optimizer、seed、precision、parameters | 參數不能脫離資料版本 |
| ValidationRun | split_id、metrics、counterexamples、uncertainty、evidence_level | 訓練集誤差不可冒充盲測 |
| ProofArtifact | theorem、assumptions、proof_checker、checker_version、status | LLM 生成 proof text 不等於證明 |
| Experience | context、action、outcome、evidence、scope、status | 每個結論須有來源引用 |

## 版本演進
當資料增加時，保留舊資料版本與舊公式版本，新增研究分支；可以比較結構、參數、適用域及證據等級。當某公式被推翻時，不刪除歷史，而是新增 falsified_by 關聯並撤銷其可推薦狀態。

## 審核門檻
無 evidence_id 的公式不得發布為已驗證；無 checker output 的命題不得標為形式化證明；無 sample split metadata 的預測評估不得列為樣本外結果。

## 工程落地細則與邊界驗收

### 補充規格 1

一致性測試：對同一研究連續新增資料版本，舊的 ValidationRun 必須仍指向原始資料，不得被新特徵覆蓋。

**驗收方法**：建立可重現的測試案例，固定輸入版本與環境，記錄正常結果、錯誤結果、例外診斷及回滾證據。審核者應能追溯結果來源，而不是只看到成功提示。

### 補充規格 2

證據撤銷：當反例出現，需建立 EvidenceRevision 並標記受影響的 PublishedArtifact；已訓練模型的相關樣本也要進入重新審核佇列。

## 欄位型別與寫入責任

以下是待實作的最小契約；UUID 以字串傳輸，時間採含時區的 ISO 8601，hash 使用 SHA-256。`tenant_id` 由身分上下文決定，不能信任客戶端自行指定的租戶。

| 欄位 | 型別／必要性 | 驗證與責任 |
|---|---|---|
| schema_version | string，必填 | API 拒絕不支援的主要版本 |
| research_id / research_version_id | UUID，必填 | 研究服務驗證版本屬於同研究及租戶 |
| dataset_version_id / equation_version_id | UUID，執行時必填 | 不可指向尚未完成校驗或已撤銷的版本 |
| run_id / attempt_id | UUID，必填 | 重試保留 run_id，另建 attempt_id 記錄每次嘗試 |
| seed / environment_digest | integer / string，必填 | 計算器保存種子、依賴鎖與容器 digest |
| evidence_ids | UUID array | 發布時至少一筆有效證據；審核服務檢查來源 |
| revision | integer，必填 | 可變的審核／狀態記錄使用樂觀鎖；產物內容不可變 |

### 驗證產物範例

下列識別碼以占位字串示意引用關係，並非可直接提交的 API 請求。

```json
{
  "schema_version": "1.0",
  "research_version_id": "<research-version-uuid>",
  "run_id": "<run-uuid>",
  "dataset_version_id": "<dataset-version-uuid>",
  "equation_version_id": "<equation-version-uuid>",
  "split_id": "<held-out-split-uuid>",
  "metrics": {"rmse": 0.012, "metric_version": "1.0"},
  "evidence_level": "SUPPORTED_EMPIRICAL",
  "assumptions": ["適用於已觀測範圍"],
  "artifact": {"uri": "<object-uri>", "sha256": "<64-hex-digest>"}
}
```

同一研究切換資料版本後，舊產物的 dataset_version_id 與 checksum 必須保持不變；新驗證另建 run。任何缺失引用、跨租戶引用或 checksum 不符都禁止發布。證據狀態與 E/P 雙軸的關係以 [AX-34](<../12-附錄/34-術語表與證據等級.md>) 為準。
