# 37｜決策待確認清單

> AXIOM v2.1 整合基線｜文件 ID AX-37｜狀態：設計基線（未實作）｜2026-10-19

## 1. 文件定位與決策摘要

待決項：首期數據上限、單機/GPU 規格、ChatGPT API 資料外送政策、Ollama 模型清單、RPO/RTO、資料保留、正式證明器範圍、初期領域、預算上限。每項需決策人與期限。

**設計原則**：每個規範都要能轉換成可測試的行為、可追溯的證據或明確的工程決策；凡屬目標數字均非已實測結果。

## 2. 章節專屬規格

### 待確認項目

已定：開發環境為 macOS 本地 Docker Compose；架設環境為 Windows 11 + WSL2 + Docker（見 ADR-006 與 [41-Docker本地架設指南](<../03-架構/41-Docker本地架設指南.md>)）。

待確認：Windows 宿主是否具備可直通的 NVIDIA GPU（決定 WSL2 是否啟用 gpu 佇列與 Ollama GPU 加速）；正式對外部署方式（持續以 WSL2 為運行環境或改採雲端／獨立 Ubuntu 主機）；敏感資料是否可傳外部 API；預期同時研究人數；單資料集最大尺寸；CPU／記憶體配額；研究保存年限；允許的商業授權；第一版支援哪些公式家族；初始 SLO 與預算。

### 決策順序

先確認資料與隱私限制，再決定 AI 路由；先做 P0 基準，再決定效能門檻與算力；先定 DSL，再決定公式搜尋插件介面；先定證據級別，再定前端可信度呈現。

### 基線假設

首版以單一數據為主；後端 Django/Python、前端 Vue3/TS；Docker 優先；PostgreSQL、Redis、MinIO；ChatGPT 與 Ollama 為可替換的推理服務。

## 3. 能力分解與詳細規格

### 3.1 選型原則

採 Python/Django/DRF、Vue3/TypeScript/Vite/Pinia；數學以 SymPy/SciPy/NumPy/mpmath/PySR 為主；圖形 KaTeX/MathLive/Plotly；儲存 PostgreSQL/pgvector/MinIO/Redis。

**強制規則／例外處理**：第三方套件要驗證版本相容、授權、維護、效能及隔離需求。

### 3.2 證據語彙

PROVEN_FORMAL、VERIFIED_SYMBOLIC、SUPPORTED_EMPIRICAL、LOCALLY_VALID、AMBIGUOUS、FALSIFIED、INSUFFICIENT_EVIDENCE；證明需具假設、工具版本與檢查紀錄。

**強制規則／例外處理**：不要以通用 confidence 百分比混合不同意義的證據。

### 3.3 典型案例

衰減正弦、兩個近似等價模型、遞迴數列、變點時間序列、雙序列滯後關係、純隨機序列、病態有理函數等。

**強制規則／例外處理**：每案例要有輸入、預期行為、反例、成功與失敗驗收條件。

### 3.4 待決與變更

單機或叢集、Ollama 模型、GPU 規格、API 配額、資料保留期限、證明器範圍、SLO 與合規要求需在設計審查確認。

**強制規則／例外處理**：未決事項以 owner、deadline、決策依據及預設安全選項管理。

## 4. 執行規範與設計檢查點

1. **前置檢查**：啟動「決策待確認清單」相關功能前，驗證資料版本、權限、依賴服務、研究模式及資源配額。

2. **核心處理**：依本文件第 2、3 節執行，記錄所有關鍵決策、失敗原因、所採用的假設及每一個中間產物的來源。

3. **完成條件**：輸出不僅有成功結果，也有失敗、部分成功、歧義及不可執行狀態；不得默默回退成看似正常的結果。

4. **品質檢查**：用正常、邊界、異常、對抗、重試、並行與取消情境驗證行為；保留對照測試與審核記錄。

## 6. 失敗情境與降級策略

| 失敗或風險 | 系統反應 | 留存證據 |
|---|---|---|
| 輸入不符合「決策待確認清單」要求 | 拒絕執行並提供可修正的欄位錯誤 | 輸入版本、驗證規則、錯誤代碼 |
| 依賴服務中斷或超時 | 有限次重試；超出預算即終止並保存 checkpoint | 服務版本、耗時、重試紀錄 |
| 結果彼此衝突或證據不足 | 保留候選及歧義，不提升證據等級 | 候選集合、反例、驗證集 |
| 資源配額超出 | 中止重運算，保留已完成的可信部分結果 | CPU/GPU 秒、記憶體峰值、任務狀態 |

## 7. 可執行驗收案例

**AC-37-01 正常路徑**：給定完整合法的輸入、固定資料版本與計算預算，執行「決策待確認清單」流程，必須產出可追溯的結果與完成狀態。

**AC-37-02 異常路徑**：故意提供缺欄、錯誤型別、超時或不合法狀態，必須得到明確診斷且不得產生已驗證的假結果。

**AC-37-03 重現性**：在固定輸入、版本、隨機種子與執行環境下重跑，輸出應符合預先定義的決定性或容差標準。

**AC-37-04 權限與審核**：未授權角色不得讀取或發布研究資料；審核者能查詢完整證據鏈。

## 8. 實作任務分解與交付物

| 順序 | 工作項 | 完成定義 |
|---|---|---|
| 1 | 規格與輸入輸出契約 | 完成 schema、狀態與錯誤定義，審查通過 |
| 2 | 核心流程與依賴整合 | 完成可重現的端到端最小流程 |
