日期：2026-10-21；承接 e92d65b；狀態：IMPLEMENTED（限本批正式封存登記與曝光帳本範圍；完整 T07 仍 IN_PROGRESS）。先定技術設計，再實作、實測及提交。

## 本輪交付與資格界線

接入真正 PROFILE：品質 PASS 後由可信封存 child 固定 canonical final 觀測，在 Evaluator 控制域保存 SealedTest／membership 與不可逆曝光帳本。一般自有資料無可信 Generator lineage，資格明記 OWN_DATA_SOLVER_ISOLATION；benchmark／case 為 null，不宣稱使用者未知真值。只有品質、未曝光封存及當前 journal 復原均通過才 READY，SEARCH／凍結候選／最終評分仍未實作，不能偽造 FrozenSubmission 或最終成績。

本輪提供 authority 的 reserve／consume／retire 原子核心及先消耗後讀取原語，僅供可信 Evaluator 後續整合；沒有普通 HTTP final 讀取或可任填 submission 的操作端點。用真實合成提交驗核心，不把該測試描述為產品候選凍結已完成。

## 信任與隔離

Generator／web 保持原始物件寫入者；可信 PROFILE／Evaluator worker 使用獨立 UID 10002，raw 以專用 GID 10003 唯讀分享。raw 目錄 0750、物件 0440；web 所有權不變，其他容器不掛載 raw。封存資料與 token 密鑰分別在 Evaluator 專用 volume，web／foundation／frontend 均不掛載。既有原檔需明確準備群組讀權，不能因升級直接讀取失敗或改成 world-readable。

另增 journal authority：UID 10004、獨立 volume／憑證／checkpoint，不掛 app DB、raw 或 sealed payload。PROFILE 只有 append／read RPC，不能刪檔／截短歷史。普通 web／Solver 不持 journal token；RPC 不開任何宿主埠、僅經私有通道，未認證一律拒絕。其實作只 append，不提供刪除／覆寫 API；宿主管理者與 volume 管理者仍在可信維運範圍，非 WORM／正式 D-06 驗收。

## 基礎設施邊界（本輪修正）

journal 傳輸不使用明文 HTTP：Evaluator 與 journal 之間改為專用 volume 上的 Unix domain socket（`/var/lib/axiom/socket/journal.sock`），服務 `network_mode: none`、不接 private 網路、不映射宿主埠；`group_add` 僅補 10003 raw 群組，令兩端容器以目錄 0750／socket 0660 交換訊息。框架為 4-byte 大端長度前綴加 canonical JSON、單連線單請求、上限 262144 bytes；token 置於酬載內以 `hmac.compare_digest` 比對，長度不足或非絕對路徑一律拒絕。

三個自建映像（backend、compatibility、benchmark）的基底一律以 digest 固定 `python@sha256:70729b46…`，移除可變 tag。T02 相容性 harness 是純內部網路、短命、不留任何資料的可丟棄環境，改用 `POSTGRES_HOST_AUTH_METHOD: trust` 且 DSN 不含密碼，使其不再保存任何固定憑證；此調整只限該隔離 harness，不改變產品服務的憑證邊界。

## 封存身分與曝光

SealedTest 身分固定租戶、source SHA、final rows hash 與 protocol hash，排除可重建的 Dataset／ResearchVersion ID。相同身分重用同封存 ID；不同身分也要查 CONTENT／LINEAGE token 重疊。CONTENT 對 exact SI 有理數、固定輸入順序、target、七維量綱及 time/group 計 tenant-scoped HMAC；排除列號、容器、順序、split 與 protocol。自有資料沒有可信 lineage，使用明示的本機來源標記，只可提供 Solver 隔離，不冒充可信原觀測 registry。

私有 SQLite authority 保存 metadata／membership／exposure，final bytes 為 UUID 不可變檔並逐次校驗。公開 PostgreSQL 只存不含 tokens／labels 的版本登記與來源／協定引用；ResearchVersion 原配置不改，狀態投影提供 sealed_test_id。READY 必須有同租戶、同版本、同成功 PROFILE、品質 PASS 的原生登記約束；沒有封存不得偽造 READY。

曝光狀態 AVAILABLE→RESERVED→CONSUMED，或 RESERVED→RETIRED；CONSUMED 不復活，退役保留 tombstone。兩種 tokens 以租戶／指紋版本／kind／token 唯一；按固定順序預留，相同 submission＋snapshot 冪等，其他提交碰撞拒絕。consume 的 journal 與私有 DB 皆確認後才能讀 final；取消預留保守退役，不回 AVAILABLE。

## 耐久性、復原與成本

journal 事件具 authority_epoch、sequence、previous_hash、payload hash 與 HMAC；checkpoint／密鑰獨立保留。先 fsync journal intent／checkpoint，再提交私有 DB；回滾或 crash 的 intent 仍保守重播，不恢復曝光資格。每次操作取得目前 authority 水位、驗完整鏈並重播，舊 DB 恢復到最新水位。缺 journal、截短、缺密鑰、epoch／hash 不符均 QUARANTINED／EXPOSURE_RECOVERY_BLOCKED；不以 SQLite 舊水位自稱恢復。journal 不存 labels，只存私有 token 引用及封存檔指紋；孤立登記不代表產物已提交。

PROFILE 有兩次順序固定 child（品質與封存擷取），啟用時預留 CPU／wall 最少 2×parser deadline＋控制餘裕；父程序 Meter 同時計入所有 child CPU，wall 不重置。沿 2GiB cgroup／單 concurrency／每 task 回收 pool child；journal 為基礎設施成本，不冒充已完整計費。封存副作用可早於 app DB commit，只有 AVAILABLE 孤立登記可重用，不建立公開 READY 或消耗；真正曝光 intent 不可回滾洗白。
