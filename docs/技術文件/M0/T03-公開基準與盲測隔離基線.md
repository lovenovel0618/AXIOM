# M0／T03｜公開基準與盲測隔離基線

先產本技術文件，再實作代碼、測試、檢測與實測紀錄。範圍依 [AX-31 T03](<../../企劃案/11-交付/31-工作拆解WBS與依賴.md>)，數學語意依 [AX-28](<../../企劃案/10-測試/28-數學基準測試規格.md>)，隔離原則依 [AX-05](<../../企劃案/02-流程/05-基準測試與持續學習流程.md>)。單人開發與程式自我檢查不改變資料隔離規則。

## 本輪交付與界線

1. 直接讀取權威 `docs/企劃案/contracts/benchmark-v1.json`，不複製四套資料造成漂移。只接受 PUBLIC_SMOKE_ONLY 與四個既定案例；拒絕未知欄位、重複 key、NaN／Infinity、bool 假扮數值、不合法切分與預期值漂移。
2. 實作標準函式庫的固定公開 oracle／評分模組。只提供 B-LINE、B-DOMAIN、B-AMBIG、B-NOISE 的已登錄候選，不接受公式字串執行，不呼叫 eval／exec 或產品 evaluator；完整 DSL 與安全求值器仍是 M1 工作。
3. 產生白名單式 Solver 投影：只有公開案例 ID、visibility、fit／development 的 row_id／x／y。排除 candidate、baseline、expected、final_test 與其 labels。沒有觀測切分的 DOMAIN／AMBIG 案例保持獨立公開參考測試，不擅自造出三區切分。
4. 在隔離 Linux 容器以真實不同 UID 驗證資料可讀性；使用一次性隨機 canary，無正式題目、答案或 blind seed 寫進版本庫。
5. 增加反例／失敗回歸、CI、嚴格型別與 Sonar 檢測，保存 [實測紀錄](<T03-驗證紀錄.md>)，commit／push。

公開案例原本就包含答案與 final_test，刪欄位只能測試投影契約，不能讓開發者重新變成未知真值。canary 只驗證作業系統檔案權限，不代表 API／bucket／DB／事件／日誌、重試 ledger 或正式未知家族盲測已驗收；產品案例仍 NOT_RUN，D-03 不自動核准。

## 固定 oracle 與可重用評分

| 案例 | 獨立參考 | 必須保存的差異 |
|---|---|---|
| B-LINE | Fraction 精確計算 2x+1；候選採浮點求值 | 三區逐點比較、MAE／RMSE／coverage，不從 fixture.expected 反向產生答案 |
| B-DOMAIN | 明確固定非零列為1、零列無定義 | 不約掉 x/x 的零點；DOMAIN_VIOLATION 計入失敗分母 |
| B-AMBIG | Fraction 的12項 sine Taylor 參考，限制 abs(x)≤1；候選使用 math.sin 與 identity | 窄域兩者相容量測誤差但不推論唯一；x=1 可區分，不自動改研究域或採樣 |
| B-NOISE | Fraction 殘差計算候選10與零 baseline | MAE=10／1、RMSE=sqrt(101)／1；只能說該候選不優，不證明資料隨機 |

評分輸入為已固定 observations 與 predictions，使用完整 selected_count：缺少預測、None、非有限結果及域錯誤都算 failed，不能縮小分母。metrics 在 valid 子集計算；沒有有效列時 MAE／RMSE 為 null，coverage=0；selected_count=0 同樣不得 PASS。容差逐點為 atol+rtol*max(abs(prediction),abs(observation))，值須有限且非負；coverage<1 不可通過。拒絕多餘預測及非法 observation，不靜默對齊。

MAE／RMSE 採縮放後累加避免先平方溢位；計算溢位仍計失敗，不輸出 NaN／Infinity。這是公開測試評分，不輸出正式證據等級、家族命中率、CI 或研究 SUPPORTED 判定。

## 資料形狀與追溯

- 基準來源及 SHA-256、版本、visibility、atol／rtol 隨報告保存。報告 scope=PUBLIC_REFERENCE_ONLY、product_status=NOT_RUN，不能當正式 Gate PASS。
- 切分只接受非 bool 整數 row IDs，三區非空、唯一、不重疊、完整覆蓋有效範圍。B-LINE／B-NOISE 固定原有6／2／2順序；時間／群組切分的通用演算法留到資料服務實作，不冒充已完成。
- 所有預期值由固定 oracle 獨立計算後與權威預期逐項比對；更改 fixture 資料或 expected 不能直接獲得新的成功基線。
- Solver 投影由新物件重建，不能淺複製或沿用來源 dict；測試額外加入敏感欄位時必須拒絕或不投影，不能因新欄位默默外洩。
- 不接受私有 suite 路徑作正式盲測輸入；本工具只處理公開固定 smoke 契約，對別的 visibility 直接拒絕。

## 真實 UID 隔離驗證

Docker 專用 harness 不掛載宿主目錄、不連網，使用 T02 相同的 Python image digest。父程序只在短命容器內以 root 準備 synthetic 公開資料與隨機 canary，隨後用 subprocess 的 user／group／extra_groups 啟動實際權限受限的子程序：

| 身分 | UID／GID | 公開投影 | 封存目錄及 canary |
|---|---|---|---|
| Solver | 10001／10001，清空 supplementary groups | 可讀 | 列目錄及開檔必須得到 PermissionError |
| Evaluator | 10002／10002，清空 supplementary groups | 可讀 | 可讀；與父程序核對 canary digest 後，只發布可讀性布林結果 |

封存目錄700、檔案600，由 Evaluator 擁有；父層可遍歷，避免只是父路徑不存在造成假拒絕。子程序確認實際 UID，Linux effective capabilities 必須為0。不存在檔案、錯誤 UID、超時或其他錯誤都 FAIL，不能把 FileNotFoundError 當成功拒絕。子程序不輸出內容、公式、seed 或檔案清單，父報告不保存 canary digest／nonce。

本機非 Linux root 環境明列 NOT_RUN、退出2，不模擬 setuid 成功。實際容器加 network=none、CPU／記憶體／pids 上限；這只證明單一容器內的 POSIX 讀取邊界，不是惡意任意程式的完整 sandbox，也不宣稱可以抗宿主 root／Docker 管理者。

## 驗證案例

| 組別 | 情境 | 預期 |
|---|---|---|
| Oracle | 四個原始公開 fixture／資料或 expected 被修改 | 原版通過；篡改失敗，不能生成假基線 |
| Metrics | 缺列、域錯誤、全部失敗、空集合、非有限數 | 完整分母、失敗原因、null 指標及不得 PASS |
| Metrics | 非法容差、長度超出、非法觀測、極大有限誤差 | 明確拒絕或穩定有限結果，不溢位成成功 |
| Projection | 候選、expected、final labels 或新增秘密欄位 | 不出現在 Solver 投影；原始資料不被修改 |
| Split／JSON | 重疊／重複／越界／bool row ID、重複 key、未知 visibility | 拒絕，不評分 |
| Real isolation | 不同 UID 的實際開檔與目錄存取 | Solver 拒絕，Evaluator 可讀；核對身份及 capabilities |
| Isolation negative | 檔案遺失、權限被放寬、身份錯誤或子程序失敗 | 必須 FAIL，不宣告隔離成功 |

下一步 T04 才接入 Django／DB／Celery／物件儲存的產品骨架；屆時再把本輪公開 oracle、投影與反例用於真實服務整合，另外完成租戶、盲測 ledger、憑證及輸出通道隔離。

## 題目級分區的參考驗證

另交 `tools/benchmark/partition.py` 的合成資料參考驗證，輸入 case_id、family_id、source_group、partition；partition 只允許 TRAIN／DEVELOPMENT／SEALED_TEST。case ID 必須唯一，三種來源識別必須非空。同 family 或 source_group 跨不同題目分區即拒絕；family 與 source 的命名空間分開，不能因不同欄位碰巧同名而誤判。相同 family 多題放同一題目分區合法；同題 fit／development／final_test 依原公開切分處理，不把題內 split 當題目分區。

回歸只用明示 synthetic 的家族／來源 ID，不建立正式私有題庫。參考驗證相信已提供的來源標記，不自行判斷公式等價、原始觀測來源或阻止使用者改名洗白；可信來源登錄、別名／lineage 與交易約束仍須產品服務實作。

## 重現指令

在倉庫根目錄執行。公開 oracle 與單元測試使用現有文件工具環境，不新增產品依賴：

```sh
.venv/bin/python -m tools.benchmark.public_oracle
.venv/bin/python -m unittest discover -s tests -v
.venv/bin/pyright
```

可選 `--output` 保存公開報告、`--projection-output` 保存 Solver 白名單投影。輸出不可與來源或彼此使用相同路徑／symlink／hardlink；無法保存投影或報告時回 FAIL，不把先前已算出的結果誤報 PASS。

真實 UID 驗證只在專用容器執行；`--user 0` 是一次性 ownership 準備所需，兩個讀取子程序仍分別降到10001／10002，且 effective capabilities=0：

```sh
docker build -t axiom-t03-isolation -f tools/benchmark/Dockerfile tools/benchmark
docker run --rm --user 0 --network none --memory 128m --pids-limit 32 --cpus 1 axiom-t03-isolation
```

映像預設是非 root 的 probe 帳號，未明確允許 setup 時回 NOT_RUN／退出2；macOS 直接執行 `.venv/bin/python -m tools.benchmark.isolation_probe` 同樣回 NOT_RUN／退出2。CI 的 benchmark-isolation job 使用相同容器指令，輸出留在 runner artifact，不在 CI 中改寫已提交的實測檔案。
