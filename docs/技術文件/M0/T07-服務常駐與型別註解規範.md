## 服務與測試證據

區分可丟棄測試環境與使用者可操作的開發環境。前者可在測試後清理；後者使用預設 axiom-dev Compose 專案，完成工作後保留運行及 volume。不操作其他專案。開發服務僅監聽 loopback，前端 15173、後端 18000；以真正 HTTP 健康檢查、登入／CSRF、三格式 INGEST→PROFILE 及 worker 持久結果驗證，不能只靠單元測試或容器存在就宣稱整合成功。記錄服務名稱、狀態、端口、測試指令及結果，未來交接需明示是否仍在運行。

本機未追蹤 .env 保存 COMPOSE_PROFILES=ingest,profile、服務啟用與完整容量限制，不輸出／提交秘密；開發來源限本機有權使用的公開／合成資料。無需重新輸入一次性 shell 環境變數才能保留啟用設定。

## 型別規範

Python 3.13／Pyright strict，前端 TypeScript strict、noUncheckedIndexedAccess，IDE 使用專案 .venv-backend，CI 必須驗同一設定。每個函式參數與回傳均標註，self／cls、框架 migration 產生的結構依工具規則處理。

JSON schema 只負責執行期結構驗證，不等於靜態型別。既有 JsonObject=dict[str, Any] 是動態相容邊界，不能以 strict 零錯誤宣稱其鍵及值都受檢查。逐步收斂此技術債；本輪將資源用量、限額、用量回報及其核心算術改為具體 TypedDict／Literal；從 JSON／ORM 載入後先驗證，再交有型別核心。不得以 cast、type: ignore、關閉規則或把新資料包成 Any 取代驗證。

新增型別政策檢查：所有 Python 函式具參數／回傳標註；正式代碼各檔的 Any／JsonObject 使用量不得超過已記錄的既有額度，新檔預設零；型別核心禁止 Any、JsonObject 與型別忽略。既有額度不是通過完整型別化的證明。以錯誤 CPU 字串、拼錯欄位及缺少欄位的反例確認 Pyright 真會拒絕，不能只測合法資料能通過。

## 中文註解規範

正式 Python 模組／公開業務函式以繁體中文說明用途；關鍵流程另解釋前提、交易與鎖順序、資料信任邊界、取消／失聯、重送去重、資料遮罩及不能提前釋放預留的原因。只翻譯函式名稱或重述賦值不算詳細註解。成熟數學／解析核心的既有英文說明可保留，但需補中文流程與重要不變量。框架產生的 migration、空 __init__、純測試不強制逐行加中文；原生 SQL guard 補中文說明保護的跨表規則及回退限制。

CI 及本機均執行政策檢查、strict 型別、對應業務／整合測試、真實 Sonar、文件及 SELF_REVIEW。驗證紀錄必須列出仍未收斂的動態邊界，避免把局部改造宣稱全庫沒有 Any。
