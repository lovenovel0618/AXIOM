# T07 證據包設計

狀態：IMPLEMENTED（限本批證據包範圍）；T07 仍為 IN_PROGRESS。證據包只彙整既有已封存產物，不生成新的科學主張；本批不開啟搜尋、候選比較或對外交付。

## 交付邊界

新增 EvidenceBundle 與 `GET /api/v2/evidence-bundles/{id}`。證據包沒有獨立建立接口：只在 PROFILE 品質 PASS 且正式封存成功、版本投影為 READY 的同一交易內由系統自動登記，確保 READY 與證據同時成立或同時不成立。本批以品質報告與結構評估兩項 Artifact 作為引用證據；ValidationRun 尚未存在，`validation_ids` 一律為空，符合契約「`validation_ids` 與 `proof_artifact_ids` 至少一項非空」。

ResearchVersion 讀取回應由伺服器動態帶入 `evidence_bundle_ids`；不可變的 `version.document` 不被改寫。證據包是獨立資料列，未來狀態改變（如刪除或隔離）只動自己的 revision，不回寫版本。

讀取沿用 session／CSRF。每個請求重新驗租戶與現行研究讀取政策（與版本讀取同一條路徑），未知 UUID、跨租戶、已刪除或已隔離一律 404，不以 UUID 猜測或快取繞過刪除或分類檢查。回應附 `X-Control-Revision` 表示目前控制 revision，並維持 no-store。

本批不提供證據包刪除端點；狀態值域已含 QUARANTINED，供刪除傳播標記衍生資料，但沒有對應端點，不宣稱已可對外刪除或隔離。

## 封存及安全

證據包是 READY 版本的公開引用入口，因此不可刪除。身分欄位（id、tenant、research_version、run、created_at）不可改；狀態變更只允許 revision 每次加一，且 document 與資料列欄位必須同步，避免出現兩份真相。引用集合必須非空，投影不出任何證據的空包在程式與 DB 兩層都被拒絕。

`proof_artifact_ids` 必須指向同一研究版本、同一租戶且狀態為 AVAILABLE 的 Artifact；這在 DB guard 內逐項以集合驗證，因此無法以手寫 SQL 塞入他版本或尚未可用的產物。產物真正的可讀性仍由既有 artifact 授權與 status 決定，證據包不代替它。

證據包不代替 SealedTest／ExposureLedger 的盲測資格，也不表示最終評估已可執行；它只是把已封存的證據以契約形狀對外揭露。

## 儲存不變條件與驗證

0013 建 EvidenceBundle：同租戶複合唯一鍵 (id, tenant)，status 的 check 限定 ACTIVE／QUARANTINED。0014 補上 native 複合 FK（research_version、run 皆指向 (id, tenant)，DEFERRABLE INITIALLY DEFERRED，對齊既有複合 FK 慣例）、BEFORE INSERT／UPDATE guard（身分不可改、revision 僅 +1、document 與欄位同步、兩個引用集合不得同時為空、每筆 proof 必須是同版本同租戶且 AVAILABLE 的 Artifact）以及 BEFORE DELETE 的不可變觸發器。

測試以真正 PostgreSQL 與成功封存的 synthetic 資料，涵蓋 READY 才建立、引用等於封存的品質報告與結構評估、`validation_ids` 為空、未知 UUID 404、刪除或隔離後版本與證據包一致 404、同 key 草稿重送不得繞過刪除或分類檢查。真 HTTP smoke 走上傳→草案→PROFILE→READY→證據包，直連與前端同源代理各一次。完整後端／工具／前端檢查、嚴格型別、文件檢查後 commit／push，並核對該 commit 的 CI。
