# M0／T01｜開發基線與驗證工具

狀態：技術設計；範圍為 AX-31 的 T01。本文先於對應程式建立；工具完成後仍不代表 T01 的決策與產品驗收已完成。

## 目標與權威

把企劃轉成可檢查的開工基線，交付當期／後續範圍、需求追溯、T01～T08 的工作依賴與責任欄，以及 D-01～09 的未決阻擋。流程沿用 [AX-31](<../../企劃案/11-交付/31-工作拆解WBS與依賴.md>)；範圍依 AX-02、階段依 AX-30、決策依 AX-37、驗收依 AX-46，工程規範依 AX-53。不建立產品 API、資料庫、搜尋引擎或部署環境。

本輪只實作 T01 的離線基線檢查程式。完成後才依 T02／T03 開始產品選型相容性與公開測試基線；不能先以文件工具的 Python 3.14 宣告 Django 或所有數值依賴已相容。使用者已確認只有本人開發，各技術角色由同一人兼任；不等待其他開發者或獨立程式 reviewer。M0 的必要決策與交付未完成前仍不關閉；不受阻擋的開發可繼續。

## 檔案與責任邊界

| 檔案 | 用途 |
|---|---|
| [t01-baseline.json](<t01-baseline.json>) | 21 項 REQ／NFR 的追溯快照、首期範圍、九項未決決策、首輪八張工作票 |
| [t01-baseline.schema.json](<t01-baseline.schema.json>) | 形狀、狀態與必要欄位；拒絕額外欄位和空白姓名 |
| [development_baseline.py](<../../../tools/development_baseline.py>) | schema、權威內容／hash、範圍與工作票依賴的離線檢查 |
| [test_development_baseline.py](<../../../tests/test_development_baseline.py>) | 真實基線及變造資料的回歸測試 |

JSON 是企劃的開工快照，不能反過來修改企劃權威。每次權威變更，先審查內容，再同步快照與來源 hash；禁止單純重算 hash 掩蓋追溯改變。程式只讀取，輸出 JSON 到 stdout，不寫入來源、不聯網、不代簽核。測試結果不寫入企劃的產品案例。

## 資料契約與語意檢查

- `schema_version` 為 `2.0`（僅本離線基線，因新增必要單人模式欄位而升版），`milestone` 固定 `M0`；`product_status` 固定 `NOT_RUN`。
- `development` 固定 `mode=SOLO`、`review_method=SELF_REVIEW`；`developer_id=project-owner` 對應使用者本人，是內部責任識別而非虛構姓名、帳號或獨立覆核者。
- `sources` 列出 AX-02／30／31／37／46／53 及能力／政策登錄的相對路徑與 SHA-256。路徑與預期來源集合固定，讀取前確認解析後仍在倉庫內，包含 symlink 也不能逸出。
- `requirements` 完整涵蓋 REQ-001～014、NFR-001～007，保存 AX-46 的 delivery、documents、acceptance、gates 原文。重複、遺漏、未登錄需求或來源不一致都失敗。首期為 REQ-001／002／003／009／010／011～013 與全部 NFR；REQ-011～013 只交首期基線，不表示後續擴充已完成。
- `decisions` 完整保留 D-01～09 的責任角色、期限、預設限制，均為 OPEN；`approved_by` 與 `evidence_uri` 為 null。此版不提供關閉決策功能。以角色名稱、工具通過或假造批准者取代決策核准一律拒絕。
- `tickets` 完整涵蓋 T01～T08，每票有 WBS、前置、交付物、角色與 owner／reviewer 責任識別欄。owner／reviewer 均為 development.developer_id，明確表示本人自我檢查；不接受 null、第二位虛構人員或將 SELF_REVIEW 標成 INDEPENDENT_REVIEW。這項規則只適用程式開發，不變更研究成果的封存分類與逐資源讀取政策。T01 保留 IN_PROGRESS，其餘 NOT_STARTED；工具不能自動關票。
- T02／T03 依賴 T01；T04 依賴 T02；T05 依賴 T04；T06 依賴 T02／T03；T07 依賴 T05／T06；T08 依賴 T07。拒絕未知依賴、重複依賴、依賴自己、環形或擅自刪除前置。
- 重複 JSON key、NaN／Infinity、超過浮點範圍數值及非 object 根節點均拒絕。不接受 JSON schema 未知欄位。

人員基線已依使用者確認設為單人；語法檢查不能認證真實簽核。D-08 的人數部分已確定，預算、領域與排程仍未決，不得整筆標核准。未決範圍沿用 AX-37，D-01／03／08 阻擋各自 M0 結束／承諾範圍；其餘決策依各自啟用或正式上線期限，不一律阻止 T02／T03 調研。

## 命令、結果及錯誤

在倉庫根目錄使用既有 `.venv`，執行依賴沿用企劃文件的 requirements-dev.txt，不新增產品套件。

```sh
.venv/bin/python tools/development_baseline.py
.venv/bin/python tools/development_baseline.py --require-m0-ready
.venv/bin/python -m unittest discover -s tests -v
.venv/bin/pyright
.venv/bin/python docs/企劃案/tools/check_docs.py
```

| 情境 | 結果／退出碼 |
|---|---|
| 基線一致、單人責任已設定，決策未核准 | `validation_status=PASS`、`m0_ready=false`，列 blockers；退出 0 |
| schema、hash、需求、單人責任或依賴錯誤 | `validation_status=FAIL`、`m0_ready=false`、errors；退出 1 |
| JSON 損壞、缺檔或檔案不可讀 | 可讀錯誤 JSON；退出 1，不輸出原始檔內容 |
| 加 `--require-m0-ready`，驗證有效但 M0 尚未完成 | 退出 2；這是預期的尚未就緒狀態 |

`m0_ready` 在本版始終為 false：工具尚無驗證決策關閉或 M0 全部交付的機制。單人自我檢查不會把整個 M0 變成已完成。普通 CI 檢查有效性；M0 關閉需先完成其餘交付並保存本人確認的決策及實測證據，不能單靠工具或人數設定放行。

## 測試與代碼檢測計畫

| 編號 | 測試輸入／操作 | 預期 |
|---|---|---|
| UT-T01-01 | 真實基線與權威文件 | 有效，21 需求／9 決策／8 工作票，產品 NOT_RUN、M0 未就緒 |
| UT-T01-02 | 缺少／重複需求、改 trace 或 MVP 範圍 | 失敗，指出對應需求 |
| UT-T01-03 | 修改權威內容、路徑越界或 symlink 指向外部 | 失敗，不讀取倉庫外資料 |
| UT-T01-04 | 未知／自我／環形依賴、刪除或重複前置 | 失敗，不能跳過工作順序 |
| UT-T01-05 | 單人 owner／reviewer 相同、不同責任 ID、空白 ID 或偽造核准 | 本人自我檢查有效；不同責任、空白及偽造核准失敗 |
| UT-T01-06 | 重複 key、非有限數、格式錯誤、未知欄位／非 object | 失敗，不崩潰或宣告有效 |
| UT-T01-07 | CLI 的一般、嚴格、異常退出 | 分別退出 0／2／1，輸出可解析 JSON |
| UT-T01-08 | 不同工作目錄執行工具 | 以腳本位置找倉庫，結果一致 |

Pyright strict 同時涵蓋工具與測試；Sonar Python analyzer 檢查新代碼，維持 Cognitive Complexity 15 上限，不停用規則或壓掉診斷。CI 先跑本輪單元測試與有效性檢查，再跑原有契約檢查。產品測試另按後續交付建立。

## 本輪完成與下一步

本輪技術交付需有上述程式／資料、回歸測試、型別與 Sonar 檢測、文件驗證及 commit／push。技術交付完成只表示 T01 的工具已可用；T01 不等待其他人員，仍需完成決策與範圍工作，不能自動標成完成。

下一步 T02：先寫相容性驗證技術文件，實測產品 Python／Node、Django／DRF／Celery、資料庫 adapter 與數值套件的最小組合，保存兩平台已測／未測界線與鎖檔，再依測試結果進 T04。T03 可並行設計公開 oracle 與盲測隔離；此處未實際執行 T02／T03。

## 單人開發修訂

依使用者確認，日常工作由本人依序完成技術文件、代碼、測試、靜態檢測、自我檢查、commit 與 push；AI 是輔助工具，不計為第二位人員。T02／T03 的並行僅表示依賴允許，實際預設先 T02 再 T03，不假設有團隊可同時施工。研究成果的封存分類與逐資源讀取政策保持原契約；沒有另一位符合資格者時，可持續本地開發、研究及查閱有權讀取的開發結果，不能創建第二帳號或自稱作者讀取封存盲測答案。
