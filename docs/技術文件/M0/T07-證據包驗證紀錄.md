## 交付範圍

新增 EvidenceBundle 模型（migration 0013／0014）與 `GET /api/v2/evidence-bundles/{id}`，回應附 `X-Control-Revision`。證據包沒有獨立建立接口，只在 PROFILE 品質 PASS 且正式封存成功時，於投影 READY 的同一交易內由系統自動登記；引用集合為該次封存的品質報告與結構評估 Artifact，`validation_ids` 為空（ValidationRun 尚未存在）。ResearchVersion 讀取回應動態帶入 `evidence_bundle_ids`，不改寫不可變的版本文檔。

讀取沿用 session／CSRF，每一請求重新驗租戶與現行研究讀取權；未知 UUID、跨租戶與撤權後一律 404。前台研究檢視在 READY 版本才顯示證據包欄位，並以契約形狀解析（兩個引用集合皆空時不採用）。

## SELF_REVIEW

- 證據包只在品質 PASS 且封存成功時登記；未封存、品質 BLOCKED 或未投影 READY 時不得出現證據包，也不得讓版本先 READY 再補證據。
- `bundle_document` 在引用集合為空時即拒絕（503 DEPENDENCY_UNAVAILABLE），不產生空包；DB guard 再驗一次，程式與資料庫兩層一致。
- proof 集合以 `sorted` 比對兩份封存 Artifact，避免以順序掩蓋引用錯誤；`validation_ids` 明確為空，不假造 validation 引用。
- 撤權後版本讀取、證據包讀取與同 key 草稿重送皆 404；授權不是只在建立時檢查一次。
- DB guard 逐項驗證 proof 指向同版本、同租戶、AVAILABLE 的 Artifact，手寫 SQL 亦無法塞入他版本或不可用產物；身分欄位不可改、revision 僅 +1、document 與欄位必須同步。
- 前台 `parseEvidenceBundle` 對兩個引用集合皆空回 null，不以半解讀資料顯示；未知狀態碼不通過。
- 本批不提供 `/revoke`，REVOKED／QUARANTINED 僅為值域預留，未以任何端點宣稱可撤銷。證據包不代表 SealedTest 盲測資格或最終評估可執行。

### SELF_REVIEW（補批）

- `newKey()` 移除 `Math.random` 備援：冪等鍵在缺 Web Crypto 時直接失敗，不以弱隨機充數；vitest（node 環境）與瀏覽器皆具 `crypto.randomUUID`。
- `parseQualityReport` 只重排結構；`validation_ids`／`proof_artifact_ids` 的「任一項不符即整份拒絕」與「兩集合皆空即拒絕」行為不變。
- Compose 長行改多行清單與折疊純量後，`docker compose config` 對兩個檔案的 image 值仍是原本釘定的 digest，服務全數 healthy。
- 本機 `.env` 啟用 INGEST／PROFILE，`catalog_smoke` 需要預設關閉的 gate，故另起可丟棄堆疊 `axiom-sqcheck`（18001／15174）驗證後整組移除；不以 `axiom-dev` 的結果冒充。
- 靜態分析零項目不是產品驗收，企劃驗收維持 NOT_RUN。
