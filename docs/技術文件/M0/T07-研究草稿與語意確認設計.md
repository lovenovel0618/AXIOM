# T07 研究草稿與語意確認設計

狀態：IMPLEMENTED（限本批草稿範圍）；T07 仍為 IN_PROGRESS。先固定設定，再由可信 PROFILE 驗證資料；本批不開啟搜尋、最終評估或對外交付。

## 交付邊界

實作既有 v2 Research 建立／列表／讀取、ResearchVersion 建立／列表／讀取。使用現行 session、CSRF、24 小時冪等與離線 schema。單人模式 Research 僅 owner 可讀寫，其他 actor 無隱含權限；版本再檢查來源目前存在的 Dataset。建立版本與讀取版本都依該來源的 access_class 政策。刪除或隔離後版本列表、單筆與冪等重送皆不能取得快照。

草稿僅接受已成功 INGEST 的 AVAILABLE DatasetVersion，精確引用 METADATA_ONLY 的欄名及列數。人工確認單一 input、target、7 維 SI 單位、正比例加偏移的轉換、量測解析度與理由、固定有理數 domain 及評估政策。欄位必須存在，input/target 不得共用來源或 alias；domain 必須對應 input，端點使用已約分有理數，區間非空。十進位使用精確比較，不用 float 判斷正數。預算沿 canonical JSON 的整數限制；不宣稱已啟用研究額度帳本。

本批提供 IID_ROWS／EXPLICIT、time_ordered=false、group_column=null、無窗口與無 refit 的研究草稿。時間／群組需要可信來源值排序、群組 digest 及相依性驗證，refit 需要不可變政策 Artifact；這些有效但尚未實作的設定明確回 503 DEPENDENCY_UNAVAILABLE。矛盾設定回 422 INVALID_SCHEMA，不靜默改成 IID。BLOCK_BOOTSTRAP 不可套用獨立觀測。ABSOLUTE_BOUND 及 practical_scale_override 必須嚴格正數；未知誤差保留 UNSPECIFIED，不自動推定正確性。

IID_ROWS 只接受 axiom-iid-sha256-v1：按 SHA-256(canonical JSON ["axiom-iid-sha256-v1",seed,row_id]) 升序排列（同 hash 再按 row_id），以 floor(0.6n)、floor(0.8n) 作邊界再排序各區原始 ID，n 至少 5；伺服器重算比對，不接受偽稱由 seed 生成的任意集合。EXPLICIT 保存使用者明示的 splitter_version，不宣稱已證明觀測獨立。

三區均非空，零起算原始 row ID 不得重複、交疊或越界，且 IID/EXPLICIT 必須完整分配所有列，避免暗中刪列。伺服器產生 split UUID 及分區 row_ids_hash；排序後固定集合，來源 dataset_version_id 必須相同。hash 輸入為 {fit,development,final_test} 的 canonical JSON。新草稿所有結果引用為空，status=DRAFT、revision=0、usage=0；不產生 Run 或假造品質結果。

## 封存及安全

sealed_final_test=true 表示固定最終列的存取政策，所有 raw Artifact 的普通 HTTP 讀取沿既有規則拒絕。sealed_test_id、benchmark_partition_id、benchmark_case_id 皆 null；本批尚未登記 SealedTest／ExposureLedger，不建立正式 blind 資格，亦不提供最終評估入口。DRAFT 不能進 READY，直到 PROFILE、fit 結構／品質、正式封存及研究帳本等前提實作並通過。版本配置無 PATCH；修改另建版本，將來登記封存時仍必須查跨版本／來源重用，不能以新草稿重設曝光資格。

Research 不依資料集建立，只有 owner 可見；版本列表在 SQL 查詢層過濾目前可見的 Dataset access_class，再做有界分頁。游標簽章固定 actor、tenant、父容器及排序，15 分鐘有效，不跨 API 使用。POST 於 actor 鎖下原子建立 provenance、記錄、audit、冪等結果；重送重新檢查 tenant 與現時 access_class，不以快取回應繞過刪除或分類。所有 HTTP 回應 no-store。

## 儲存不變條件與驗證

Research／ResearchVersion 的 owner、父層、資料版本、provenance 使用同租戶複合 FK。Research 身分不可改；本批版本整列不可變，DB 插入 guard 對齊 JSON 身分、父層、初始 DRAFT 與空結果／封存引用，拒絕直接 SQL 假 READY。後續狀態機需獨立 migration 與可信交易，不先放寬。

測試使用真正 PostgreSQL 與成功 INGEST 的 synthetic 資料，涵蓋 HTTP 重開／分頁／schema、精確數值邊界、非法列集合、來源混用、刪除或隔離後冪等、租戶隔離、直接 SQL 改寫及原子回滾；真 HTTP smoke 從上傳到研究草稿。完整後端／工具／前端檢查、嚴格型別、實際 Sonar、文件檢查與單人 SELF_REVIEW 後 commit/push，並核對該 commit 的 CI。
