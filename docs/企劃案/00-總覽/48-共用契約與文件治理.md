## 共用資料與錯誤約定

UUID 使用標準 UUID 字串；時間為 UTC RFC 3339，顯示時轉使用者時區。SHA-256 為小寫 64 位十六進位。每個可發布產物包含 schema_version、不可變來源版本、產物 checksum、環境 digest 與產生者。精確數以整數／有理數／十進位字串表示，禁止 JSON NaN／Infinity。

缺失、null、空集合有不同意義：必要值不可用 null 代替；可空欄位須明列；未知指標輸出 null 並附 reason，不能填 0。以環境 digest 固定依賴，seed 只控制支援種子的演算法；非決定性實作需聲明容差與適用硬體。

錯誤 envelope 為 code、message、details、request_id、retryable。details 為欄位／限制的結構化清單，不含秘密。穩定錯誤碼以 contracts/error-codes-v1.json 為單一真實來源，權威語意見 AX-21，並與 OpenAPI Error.code enum 雙向校驗。重試須同時服從任務與研究總預算；未知錯誤不得提升證據級別。

## 版本及變更程序

1. 變更者填寫需求、受影響契約、相容性、遷移及回退條件；不可變產物以新增版本取代覆寫。
2. DSL/schema/API 破壞相容的改動升 major；新增相容能力升 minor；文件文字修正不暗改契約版本。
3. 先修改權威文件與對應 schema，再更新引用章節、驗收 fixture、追溯表與索引。
4. 跑文件驗證工具後重建 MANIFEST；程式實作、正式基準與發布簽核是不同工作，不得以文件檢查代替。

## 嚴格JSON與固定canonical profile（v2.9）

JSON入口拒絕重複member（含跳脫後同名）、NaN／Infinity／-Infinity及1e400等解析後非有限數；不能保留最後一個值或交不同parser自行選。限額／深度在完整讀取前有界執行，錯誤不可附原始秘密。普通Artifact內容可保存合法有限浮點數，sha256對原bytes計算，不因反序列化重寫內容。

用於DSL／binding／split／policy／plan／submission／config身分的axiom-canonical-json-v1另採固定受限格式：UTF-8、無BOM／空白、字典key按Unicode scalar code point排序、陣列保留順序、字串不做Unicode normalization，拒絕未配對surrogate；null／boolean正常JSON，小數與精確量用欄位定義的十進位／有理字串，JSON numeric只接受±(2^53-1)內整數，禁止hash payload含float。深度最多32、canonical bytes最多2MiB；超限在預留final前拒絕，不能自動截斷。不同語言必跑相同字節向量，不能以JS預設UTF-16 sort／float serializer假定一致。Artifact內容hash與此邏輯身分hash是不同用途，欄位名必區分。

decimal正規化僅對宣告的數學欄位執行：去小數尾零／多餘小數點，-0→0，禁止exponent；例如2.00→2、-0.0→0，不改source_column或一般文字。擬合服務先正規化FitRun.parameters，再計parameter_binding_hash與凍結；非canonical binding副本拒絕，不以Decimal預設精度normalize造成捨入。canonical JSON序列化本身不猜字串是不是數值。既有曝光rational化與SI轉換仍在其專用階段，正式部署後更改profile需版本遷移，不回算／重設曝光。
