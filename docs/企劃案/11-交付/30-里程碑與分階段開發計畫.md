# 30｜里程碑與分階段開發計畫

> AXIOM v2.9 設計規格｜文件 ID AX-30｜狀態：待實作、待驗收｜2026-10-20

## 唯一階段定義

本表取代 v2.1 內兩套 M0～M6/M7 定義。REQ 優先級與階段是不同維度；M3 完成才可稱首期可互動 MVP，M2 是引擎能力交付。記憶、AI 與自動訓練不屬於 MVP 必要依賴。

| 階段 | 核心交付／需求 | 完成閘門 | 規劃估算 |
|---|---|---|---|
| M0 規格與基準設計 | DSL v1、物件/API 契約、fixture、決策表 | 契約相容、盲測權限設計與追溯表審查；未決阻擋項已解決 | 2–4 週 |
| M1 可信數學核心 | REQ-001／003／010及REQ-011～013基線；結構確認、決策chunk、匯入、求值與證據 | 精確 fixture、惡意輸入、域限制及重現案例通過 | 4–8 週 |
| M2 單序列引擎 | REQ-002；線性、多項式、固定頻率諧波三策略 | AX-28 固定案例通過；最終測試未參與搜尋 | 6–10 週 |
| M3 互動 MVP | REQ-009；資料→搜尋→比較→證據→人工發布 | P0 需求追溯完整；G1/G2/G4/G5/G6/G7 通過，G3 以外部 AI 停用政策驗收 | 4–8 週 |
| M4 記憶與 AI | REQ-004／005、REQ-011～014擴充；受限表徵、HRR、檢索、AI紀錄／整理與可替換Gateway | 固定預算 no-memory 對照、權限及外送政策通過 | 6–10 週，須重估 |
| M5 推演與證明 | REQ-006／013；有前提的正逆推導、多路徑證據及選配checker | 定義域、前提與 checker 反例測試；不要求所有命題均能證明 | 待 M4 後估算 |
| M6 雙序列與低維表徵 | REQ-007／011／013；雙序列、二／三維座標、對齊／時滯與有條件反演 | 時序／假相關專屬基準及拒答通過 | 待估 |
| M7 多維多序列與策略訓練 | REQ-008／011／013／014；受限n維、多序列、狀態重建、策略及選配微調 | 分家族回歸、負遷移、成本及資料授權閘門通過 | 待估 |

已確認目前只有使用者本人一人開發，Backend／Frontend／Math／QA／SRE 為本人兼任的工作面向；以單人依序交付估算，不把可並行依賴視為多人產能。尚無速度與預算基線，週數不可視為承諾日期或直接加總成排程。日常程式開發採自我檢查與自動化測試，可直接 commit／push，不等待另一位開發者。研究成果 PublishedArtifact 的作者／獨立審核規則維持原契約；缺少該審核者只阻擋該成果正式發布，不阻止開發、測試或本地研究。

## 依賴及變更

M0→M1→M2→M3；M4 依賴已可驗收的 M3，M5／M6 依各自契約審查後排程，M7 需先有資料授權與隔離基準。每階段交付包含 schema、實作、測試證據、部署／回退與已知限制。

需求擴大需先更新 AX-02、AX-31、AX-37、AX-46，不可只改本表週數。正式上線前需要 AX-27 的恢復演練；資料未有備份不能因 MVP 而免除。

## REQ-011～014的分段完成

每項需求必須按AX-49～52列出的子能力分段驗收，不能因M1保存了結構報告就把整個自主表徵搜尋標完成。M4表徵仍需可回原單輸入DSL；M6／M7新增多變量、ODE、空間資料及多序列時凍結新major契約與遷移，不能擴充同一DSL v1卻宣稱相容。ATME批次整理／訓練屬後續受控內部job，現行六種Run／TaskInput不默默新增類型；真正開工前要另交付job狀態、取消、預算及恢復API／schema。
