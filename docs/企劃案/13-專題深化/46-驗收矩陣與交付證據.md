## 開發與產品交付的界線

目前由使用者本人一人開發，日常程式與文件可以由本人自我檢查、完成測試與代碼檢測後 commit／push，不需要另一位程式 reviewer。研究成果的封存分類與逐資源讀取政策仍維持原契約，不以本人切換身分或 AI 代替；有關正式產品交付的其他 Gate 也仍需實際證據。單人開發本身不是停止實作、測試或本地研究的理由。

## 記錄格式、簽核與回退

每筆結果包含 requirement_id、document_id、gate_id、test_id、release_version、environment_digest、dataset_hash、expected、actual、result、evidence_uri、executor、executed_at。result 只允許 PASS／FAIL／BLOCKED／NOT_RUN；未跑不填 actual 或 PASS。Gate 可因不適用而註記範圍，但不得將未啟用的正式能力算作驗證成功。

所有 gate 通過且證據完整後才可交付；false proof、資料洩漏、越權與證據不可追溯不得豁免。非當期需求須正式修改範圍與追溯表，不以口頭說明跳過。D-03／D-06 未關閉，G2／G7 均保持 BLOCKED。

交付包含需求、ADR、schema/API、測試與效能報告、資安與資料分級清單、映像／模型／DSL 版本、部署 Runbook、相容 BackupSet、已知限制及紀錄。回退先停寫／排空，再切相配映像、組態與 schema；不相容遷移從快照恢復並重播刪除 ledger，完成 AX-27 驗收後開放。

| ID | 交付檢查 | 預期 |
|---|---|---|
| AC-46-01 | MVP 追溯清單少 REQ-003 或缺案例 | G1 BLOCKED |
| AC-46-02 | 有數學報告但 D-03 OPEN | G2 BLOCKED，不可預填通過 |
| AC-46-03 | 缺 environment_digest 或證據不可追溯 | 拒絕結案，列缺失欄位 |
| AC-46-04 | 不相容 DB 遷移只降映像 | 回退驗收 FAIL，要求相配 BackupSet 與還原演練 |

研究模組由單一頁面拆為三個路由，共用同一條研究線查詢狀態與 `ref` 回跳來源；下表只宣告覆蓋與阻擋關係，全部產品案例維持 NOT_RUN。

| 拆分範圍 | 產品案例 | 主責／gate |
|---|---|---|
| 研究清單（`research-list`，`/researches`） | AC-23-08～09、AC-24-17～18 | Frontend/QA，G6 |
| 新建研究（`research-create`，`/researches/new`） | AC-23-10、AC-24-19 | Frontend/QA，G6 |
| 研究工作台（`research-workbench`，`/researches/:id`） | AC-23-03、AC-24-01～16 | Frontend/QA，G6 |

清單頁與精靈只以本頁已讀取的研究、版本與任務推導，未讀取範圍以版本 ID 明示並標示「未取得」，後端仍有未讀取版本頁面時標示 `+`；後端尚無批次刪除／批次派送端點，批次動作只做彙總檢視與匯出，自治理策略（AUTO／DEEP）與外部傳輸審核因後端無對應欄位或端點而不提供、也不以預設值送出。文件與前端推導層測試（`researchCatalog.test.ts`）通過不代表上述產品案例已實作驗收。
