# 27｜可觀測性備份與故障復原

> AXIOM v2.9 設計規格｜文件 ID AX-27｜狀態：待實作、待驗收｜2026-10-20

## 文件定位與決策摘要

每個請求／run／attempt 以 request_id、trace_id 等連接日誌與產物，指標涵蓋 API latency/error、queue age、attempt retry、容量與用量；禁止以秘密或原始資料作 log 或 metric label。

## 觀測欄位與告警

每個請求／run／attempt 以 request_id、trace_id、tenant_id、research_version_id、run_id、generation 連接日誌與產物。指標至少含 API latency/error、queue age、attempt retry、租約回收、checkpoint 失敗、DB/物件容量、outbox lag、盲測存取拒絕、政策路由、CPU/GPU/token 用量及驗證 UNKNOWN／拒答。禁止以秘密或原始資料作 log 或 metric label。

錯誤率、queue age、容量、取消 grace 超時及已刪除／隔離快取命中告警門檻由 D-06 凍結；校驗失敗、越權或真值洩漏一經發現立即停止受影響研究並產生事件，不等待平均門檻。

## 可還原的備份集

BackupSet 包含 backup_set_id、schema/DSL/app 版本、DB restore point/WAL 範圍、物件 version_id/checksum manifest、模型／組態清單、secret_key_version 引用、outbox 高水位、刪除／隔離 ledger 高水位、建立時間及保管位置。金鑰內容不能與加密備份同放；需另有受控的金鑰復原方式。

MVP 以受控 maintenance window 建立一致集：停止接受新寫入、排空提交交易與 outbox、記錄高水位，取得 DB 一致性快照與全部被引用的物件版本清單，驗證物件可讀及 checksum，再解除 maintenance。不可只拷貝正在寫入的 DB 目錄。後續可用 PITR，但必須證明 DB restore point 引用的每個物件版本都保留。

暫定本地開發每天一次備份並保留 7 個完成集，僅是開發預設。正式 RPO/RTO、異地策略、保留與敏感資料期限屬 D-05／D-06，未定不宣稱具有正式災難復原保障。Redis 不作權威資料來源；任務與事件可從 DB 重建。

## 恢復 Runbook

| 順序 | 操作 | 檢查與失敗處理 |
|---|---|---|
| 1 | 隔離恢復環境，停 API 寫入、worker、beat、Gateway | 確認不會向外送資料或重複執行舊任務 |
| 2 | 選定完整 BackupSet、取得必要金鑰版本 | 缺 key 或 manifest 不完整則停止，不試空密碼 |
| 3 | 先還原所需物件／模型版本，再還原相配 DB 快照 | 驗證每個 DB artifact 引用可讀、size/hash 相符 |
| 4 | 檢查 schema/DSL/parser/app 相容並跑必要遷移 | 不相容先回相配映像，禁止跳過錯誤 |
| 5 | 重播備份後獨立保存的刪除／隔離 ledger | 敏感內容與模型須先隔離，避免重新對外出現 |
| 6 | 清理過期租約、generation 遞增、重建 Redis/outbox 派送 | 舊 worker 與舊憑證不能提交；事件重送去重 |
| 7 | 重建快取／向量索引，只索引有效且分類允許的證據 | 舊索引不能先行提供推薦 |
| 8 | 執行小型研究與只讀檢查，開 API 讀流量再開 worker／寫入 | 驗證跨租戶、checksum、run 唯一與事件連續 |

復原驗收至少比對：所有引用物件 hash、DatasetVersion／EquationVersion 數、未完成任務清單、EvidenceBundle 有效性、刪除 tombstone、模型狀態及 idempotency ledger。發現缺檔時標記不可用並保持受影響範圍關閉，不用新檔取代原證據。

## RPO／RTO 量測與回退

RPO=最後已確認寫入至可恢復寫入點的資料損失時間，另報實際遺失筆數；RTO=故障宣告至恢復驗收後可提供預定服務的時間。單純 DB 啟動不算服務恢復。演練保存故障時間、快照、命令／版本、檢查結果與執行者。遷移不能逆轉時從相容 BackupSet 還原，不能只降映像。

## 不可逆曝光紀錄的復原

盲測曝光不受一般資料RPO允許回退。ExposureLedger的每次RESERVED／CONSUMED／RETIRED變化另寫入與應用DB備份隔離的append-only ExposureJournal；紀錄含tenant、authority_epoch、單調sequence、前筆hash、動作、submission_id／snapshot_hash及私有觀測token引用，不存原labels。指紋規則／密鑰版本與別名亦須可獨立恢復，不能只存在待還原DB。Journal由Evaluator信任域管理，寫入者不能刪除或截短歷史；服務先驗證當前authority_epoch與連續hash鏈，不以本機快取自稱最新。

跨DB與journal無共同交易，採保守先記錄：預留／消耗／退役intent先在journal耐久寫入並取得sequence確認，再提交DB ledger與outbox。final labels讀取需journal消耗確認、DB消耗確認、有效root／attempt與分類條件全部成立。journal已寫但DB回滾時，恢復按較嚴格狀態保留預留／消耗，不將孤立intent當作未曝光；同submission按固定slot恢復。journal不可用時禁止新的封存預留及final讀取，fit/development可依正常政策繼續；不得退回只寫DB。

BackupSet新增exposure_authority_epoch、exposure_journal_high_watermark、checkpoint_hash、fingerprint/key版本引用。高水位只表示備份時點，恢復時必須從獨立authority取得目前可信高水位，先驗證hash鏈並重播至該點，不能只重播到舊備份的水位。將此步驟置於既有Runbook第5步之後、第6步任務重派之前；讀流量中可觀察final結果的路徑也須等待此閘門。

可信服務持久化ExposureRecoveryState，記backup／authority／replayed三個高水位、authority_epoch、journal_verified、key_versions_verified及VERIFIED／QUARANTINED。只有可信authority相同、鏈與金鑰驗證成功、replayed等於目前authority水位才VERIFIED；不可取得最新水位、缺段、密鑰不全或epoch不相容均QUARANTINED，拒絕正式blind派送／final讀取。隔離或復原期間authority仍有寫入時須追到新水位，並以authority的原子reserve/consume服務避免檢查後競態；不能靠一次ready檢查永久放行。

備份後已曝光而DB內無submission／slot／完整結果時，至少重建觀測資格tombstone並禁止新提交重用，不能捏造EVALUATED結果。允許保留舊已完成報告只依其真實Artifact及分類政策，不自動重跑遺失結果。無法證明曝光歷史完整時，整個受影響namespace暫停正式blind資格；完成獨立對帳或改用新且未曝光集合才可恢復。restore後輪替服務憑證／恢復epoch，舊worker不得以備份前租約讀取labels。

| ID | 情境 | 預期 |
|---|---|---|
| AC-27-05 | 備份後消耗final，再還原較早DB | 重播獨立journal後仍CONSUMED；不得重新AVAILABLE |
| AC-27-06 | journal缺段／最新水位未知／金鑰版本缺失 | QUARANTINED、EXPOSURE_RECOVERY_BLOCKED，不能重派final |
| AC-27-07 | journal已記消耗但DB提交失敗，或結果未入備份 | 保守保留曝光tombstone；不製造結果、不給新提交資格 |

研究帳本與root帳本需隨BackupSet相配還原；對備份後可能已執行、但無法完整重建UsageReport的未完成研究，恢復時保留最壞情況未結reservation並封鎖新派送，待Supervisor用量對帳完成再釋放。不得以舊usage快照宣稱恢復了完整可用餘額，或將可能已花費的額度重新發給新root。

## 分類變更、資料洩漏與復原驗證

長連線SSE在每次發送與定期heartbeat重新驗證目前租戶分區與access_class分類政策，來源刪除或隔離立即停止，不讓已登入的長連線永久保留讀取權。內容下載由服務端代理且按資料塊檢查取消／刪除；MVP不對敏感Artifact發可轉傳的長效GET URL，已離開系統的副本無法收回，需audit其下載及刪除通知。

RUN終態通知與研究判斷分開；RunFinished.stop_reason允許null，無final明細讀取資格的接收者只看公開狀態／revision，封存原因遮罩為null，不能由錯誤訊息、子run數量或payload推回final結果。ValidationFinished等密封事件整筆過濾；sequence可有缺號，不得補送隱藏內容。snapshot套同一政策。log／trace不得寫final數列、原始DSL注入片段或含資料的例外堆疊，敏感診斷只記Artifact ID；metric label禁止row／run／request等高基數ID，request ID僅入受保護的log／trace。

疑似final曝光事件先關閉封存預留／取標籤入口，隔離受影響bundle／摘要／記憶，依lineage標記所有後代。已曝光觀測不能靠重建DB／刪log／重新匯入恢復獨立性；需新且未曝光的觀測及重新驗證。事故須記影響範圍、存取修復、journal水位、金鑰可用性、恢復／再開放的獨立檢查，D-06未關閉RPO/RTO決策前只能演練，不宣稱達標。

## AI紀錄與批次整理的故障復原

TraceChunk、AIRuntimeRecord、ArchiveManifest、批次高水位及訓練來源manifest納入BackupSet，還原先重播刪除／隔離及曝光journal，確認每個DB引用的原始或封存物件可還原驗hash。斷流／write失敗保存PARTIAL／UNKNOWN；壓縮與registry切換、批次去重／水位、租約恢復故障注入依AX-52，不能只備份摘要或Redis。告警包括capture loss、archive驗證失敗、積壓、水位倒退、token使用未知與負遷移；門檻仍由D-06凍結。
