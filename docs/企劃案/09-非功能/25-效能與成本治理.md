## 文件定位與決策摘要

目標（待壓測確認）：一般查詢 p95<300ms（不含重計算）、研究提交 p95<1s、圖表 10 萬點採 LOD/降採樣；每研究預算上限可配置，超限保留部分成果。

## 章節專屬規格

### 效能預算

以 P0 實測定義 API P50/P95、前端互動延遲、候選首次出現時間、每 1,000 候選的 CPU 秒、資料處理吞吐、GPU 利用率、單任務成本；每項區分冷啟動與熱快取。

### 最佳化策略

Polars/Arrow/Parquet 降低資料搬運；FFT/向量化優先；公式 AST 快取、特徵快取、相似案例快取；候選早停、分層精度、工作池資源隔離、按預期收益分配搜尋預算。

### 成本治理

每個 run 設 CPU 秒、GPU 秒、Token、記憶體、候選數、儲存與時間預算；記錄每個搜尋策略的邊際收益；API 不可用時降級為本地搜尋但不假裝已使用雲端推理。

### 壓測情境

小資料高併發、大資料單任務、複雜公式樹、精度升級、突發多使用者、LLM 限流、物件儲存延遲；依 SLO 做容量規劃。

## 租戶准入與累計成本邊界

研究budget不能防止反覆建立新版本規避租戶配額。MVP的每租戶最多一個活躍研究根須由DB條件唯一約束／准入reservation實際保證，PROFILE與SEARCH都算活躍，安全DELETE保留獨立通道；取消未確認、失敗收斂及租約恢復仍占名額。租戶storage、CPU／LLM週期上限及週期UTC邊界是管理端政策配置；配置缺失不啟動相關能力。准入以持久租戶配額預留與run建立同交易，超限回TENANT_ADMISSION_DENIED，不先入列再檢查。建立前准入交易不反向持有root執行鎖；執行後成本仍沿AX-38鎖序，避免新增租戶鎖造成反向死鎖。

實際成本以固定最小單位或十進位定點存帳，不以累加binary float作財務／配額裁決。rounding模式、計價版本與貨幣／token單位固定，任何非零消耗不能因逐次向下取整成0；預留上取整、結算聚合後依政策捨入。worker重試消耗真實CPU／LLM照計，UsageReport重送只去除同事件重複，不能把不同attempt真實成本去掉。硬限制與軟告警分開，硬限制達線即停止新派送、既有作業受預留及監督器終止界線約束；告警不能代替硬限制。

## 表徵與整理納入總成本

特徵偵測、升降維、分支探索、重審、LLM整理、壓縮及訓練各自持有有界預留；root／研究／租戶額度不因變更表徵或重審而清零。背景整理使用隔離concurrency與租戶quota，超出就背壓／停止，不與前景研究無限制搶資源。功效報告同時列成功／失敗／未完成case及實際CPU、memory、tokens和儲存，不能只報「每次成功花費」而藏失敗探索成本。
